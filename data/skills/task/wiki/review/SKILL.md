# 文档审校

对比多篇 wiki 文档，发现：

- 同一概念在多个文档中重复定义，且定义不一致或措辞有差异
- 模糊表述——说了但读者无法据此行动或理解
- 逻辑缺口——前提、步骤、结论之间缺少承接

## 全局约定

- 链接语法：`[[文件名]]`，文件名不含扩展名
- 除非用户明确确认，**不执行任何实际编辑**
- 所有发现通过 `progress` 汇报，附建议和依据

## 执行步骤

### 1. 确定审校范围

用户可能提供：

- 单文件审校：只审这一篇的内在逻辑和表述清晰度
- 多文件审校：同时检查篇际重复和冲突
- 全库审校：扫描 wiki 目录下所有文件

先用 `observe` 列出待审文件，确认范围后再开始。

### 2. 逐篇阅读

用 `observe` 读取所有涉及文件。

### 3. 分析

用 `reason` 完成以下维度的检查：

**3a. 重复定义检查**

对于每对文档（或单文件内部不同段落），检查：

- 是否有同一概念被多次定义？
- 定义措辞是否一致？不一致的话，哪个是对的？
- 是否存在"此处同 xxx 文档所述"但实际所述内容不同的情况？

判定为重复的条件：两个段落都在解释同一个概念（不是引用，而是各自独立定义）。

**3b. 模糊表述检查**

逐段扫描，标记以下信号：

- "等""之类""等等"——列举不完整但没有说明边界
- 缺少主语或宾语的句子
- "一般情况下""通常""大多数"——没有给出例外条件
- "参考 xxx"但没有说明参考 xxx 的哪个部分
- 步骤跳跃：上一步和下一步之间缺了一个中间动作
- 术语前后不一致：同一个东西在不同位置用了不同的叫法

**3c. 矛盾检查**

- 两处对同一事实给出不同数据/结论
- 一处说"A 包含 B"，另一处说"A 不含 B"
- 时间线矛盾："先 X 再 Y" vs "在 Y 之前先 Z"

### 4. 对每个发现分类

| 等级 | 含义 |
|------|------|
| **阻断** | 读者按文档操作会出错或无法继续 |
| **严重** | 严重影响理解，但读者可能通过猜测绕过去 |
| **轻微** | 不影响理解，但降低效率或专业感 |

### 5. 汇报

用 `progress(blocked)` 提交完整报告：

```
【审校范围】N 篇文档：xxx.md, yyy.md, ...

【重复定义】（严重程度）
1. "概念A" 同时定义于：
   - xxx.md#章节（原文："..."）
   - yyy.md#段落（原文："..."）
   建议：保留 yyy.md 的定义（理由），在 xxx.md 改为引用链接 [[yyy]]
2. ...

【模糊表述】（严重程度）
1. xxx.md:42 — "等"未说明边界
   原文："支持 Markdown、HTML 等格式"
   建议：列出全部支持的格式，或改为"支持 Markdown 和 HTML"
2. ...

【矛盾】（严重程度）
1. xxx.md 说"A 必须先于 B"，yyy.md 说"B 可在 A 之前执行"
   建议：确认实际顺序后统一
2. ...

【是否需要我执行以上修改？】
```

### 6. 确认后执行

用户确认具体修改方案后，用 `write` 逐处重写修改。

## 自检

- 每条重复定义都给出了合并建议（保留哪个、为何保留）
- 每条模糊表述都给出了具体的改写方案
- 矛盾项已确认不是自己理解错误（重新读了两端的上下文）
- 不把"风格差异"当"矛盾"——比如一处用"删除"一处用"移除"，如果意思相同就不算矛盾

## 边界

- 不审校 frontmatter 元数据格式
- 不检查拼写和语法（那是另一个任务）
- 如果只有一篇极短文档（< 10 行），降级为仅检查模糊表述，不强行找重复
