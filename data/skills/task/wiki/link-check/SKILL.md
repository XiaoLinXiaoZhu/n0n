# 链接审核

检查提供的文档中：

- 哪些词语/概念在其他文档中有定义，但此处未用 `[[文档名]]` 引用
- 已有的 wikilink 是否指向存在的文档、链接文本是否正确

## 全局约定

- 链接语法：`[[文件名]]`，文件名不含扩展名
- 除非用户明确确认，**不执行任何实际编辑**
- 所有发现通过 `progress` 汇报，附建议和依据

## 执行步骤

### 1. 收集上下文

先理解 wiki 的全貌：

```bash
# 列出 wiki 目录下所有 .md 文件（递归）
dir /s /b wiki\*.md
# 或用
rg --files wiki/ | rg "\.md$"
```

将文件清单作为"已知文档索引"——这是判断"应引用而未引用"的依据。

### 2. 读取待审文档

用 `observe` 读取用户指定的文档全文。

### 3. 提取候选词

用 `reason` 完成以下分析：

**3a. 已有 wikilink 清单**

提取文档中所有 `[[...]]`，列出：链接文本、指向的目标文件名。

**3b. 检查已有链接有效性**

将已有链接与步骤 1 的文件清单逐一比对：

- 目标文件是否存在？
- 链接文本是否与目标文件名一致？（允许 `[[文件名|显示文本]]` 的别名形式，但不鼓励无必要别名）

**3c. 发现未链接的关键词**

对文档中的关键术语、专有名词、概念定义，判断是否在其他文档中有对应条目：

- 与文件清单中的文件名做语义匹配（文件名本身即是概念的标识）
- 与文件清单中其他文档的一级标题做匹配
- 也检查已有文档中 `[[反链]]` 指向本文档的概念——本文档是否做了回应

判断标准：如果某术语在其他文档中有专门章节/文件讨论，而本文档未链接，则标记为"应引用而未引用"。

**3d. 对每个发现打分**

| 等级 | 含义 |
|------|------|
| **必须** | 定义了概念但未链接到对应文档，读者无法导航 |
| **建议** | 提及概念时链接有助于理解，但不链接也能读 |
| **可选** | 可链接可不链接，由作者判断 |

### 4. 汇报

用 `progress(blocked)` 提交完整报告，等待用户确认是否执行修改：

```
【文档】xxx.md
【已有链接】N 处，其中有效 N 处，需修复 N 处

【需修复的链接】
1. [[旧名称]] → 目标文件已改名/不存在，建议改为 [[新名称]]（理由）
2. ...

【应引用而未引用】
1. "术语A"（第 N 行）→ 存在 wiki/术语A.md，建议添加 [[术语A]]（必须/建议/可选）
2. ...

【是否需要我执行以上修改？】
```

### 5. 确认后执行

用户确认后，用 `edit` 逐处修改。每次修改记录在 commit message 中。

## 自检

- 每条建议都有明确的"术语 → 目标文件"对应关系，不能只写"这里应该加链接"而不说加什么
- 链接目标必须是实际存在的文件
- 不推荐循环引用（A 链 B 且 B 链 A，除非确实互为补充）
- 不推荐在同一段落中重复链接同一目标

## 边界

- 不处理外部 URL 链接（`[text](url)` 格式），只关心内部 wikilink
- 不检查图片、附件等非 Markdown 资源的引用
- 如果 wiki 目录下文件极少（< 3 个），说明"应引用"的判断依据不足，降级为只检查已有链接有效性
