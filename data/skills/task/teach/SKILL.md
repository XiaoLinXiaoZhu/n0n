# 教学模式（Teach）

## 流程

### 1. 锚定学习目标

从用户的问题中提取核心概念。判断目标深度（知道是什么 / 能用 / 能自己实现 / 能向别人解释）。不确定时用 `show(customer information required)` 确认。

把核心概念和目标深度作为后续内容的内部基线；只有该判断会显著改变教学范围时才用 `show(production record)` 公示。

### 2. 结构提取

拆解新概念的逻辑骨架：

- 因果链（谁导致谁、瓶颈在哪）
- 关键不变量（什么不变、什么守恒）
- 反直觉点（哪一步和直觉预测相反）

输出一句话概括核心结构。只描述结构，不给类比。

形成因果链、不变量、反直觉点和逻辑骨架的内部记录。

### 3. 穷举匹配

用逻辑骨架搜索候选类比领域：日常经验、物理、编程、游戏、运动……

寻找能够从逻辑骨架推出结论的候选类比，数量由实质差异决定。排除「装饰性类比」——好看但推不出结论的
（如「数据像水一样流动」）。

比较真实候选的映射能力；没有实质替代类比时不为满足数量制造候选。

### 4. 构建可推理类比

将新概念的每个关键元素映射到类比的对应元素。验证：改变类比中的一个参数 → 预测新概念的行为 → 检查是否成立。不成立则回到步骤 3 重选。

形成类比描述、映射关系和能够检验其推理能力的验证记录。

### 5. 推导 + 反面验证

从类比推导到结论。加反面验证：「如果不这样做会怎样」或「传统方法卡在哪里」。

**退出 → `show(qualified delivery)`：** 推导链、反面验证、一句话总结。

## 反面示例

用户问："Flash-Attention 为什么快？"

- **×** 列出 Tiling 技术细节和 IO 复杂度公式。用户能背，遇到类似问题还是不会分析。
- **√** 先拆结构（瓶颈是数据搬运而非计算），匹配类比（HBM=冰箱、SRAM=切菜板——每次做菜要来回拿材料），推导（分块=一次多拿几个菜，减少来回次数所以快）。

## 自检

- 类比能推理吗？用户能拿它预测行为吗？
- 选中的类比是否优于仍与逻辑骨架相容的实质候选？
- 反面验证做了吗？
