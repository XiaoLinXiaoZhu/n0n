# 教学模式（Teach）

## 流程

### 1. 锚定学习目标

从用户的问题中提取核心概念。判断目标深度（知道是什么 / 能用 / 能自己实现 / 能向别人解释）。不确定时用 `show(ask user question)` 确认。

**退出 → `show(working log)`：** 核心概念和目标深度。

### 2. 结构提取

拆解新概念的逻辑骨架：

- 因果链（谁导致谁、瓶颈在哪）
- 关键不变量（什么不变、什么守恒）
- 反直觉点（哪一步和直觉预测相反）

输出一句话概括核心结构。只描述结构，不给类比。

**退出 → `show(working log)`：** 因果链、不变量、反直觉点、逻辑骨架。

### 3. 穷举匹配

用逻辑骨架搜索候选类比领域：日常经验、物理、编程、游戏、运动……

穷举至少 3 个候选，比较匹配质量。排除「装饰性类比」——好看但推不出结论的（如「数据像水一样流动」）。

**退出 → `show(working log)`：** 至少列出 3 个候选，至少排除 2 个并说明理由。

### 4. 构建可推理类比

将新概念的每个关键元素映射到类比的对应元素。验证：改变类比中的一个参数 → 预测新概念的行为 → 检查是否成立。不成立则回到步骤 3 重选。

**退出 → `show(working log)`：** 类比描述、映射表、至少一个推理性验证链。

### 5. 推导 + 反面验证

从类比推导到结论。加反面验证：「如果不这样做会怎样」或「传统方法卡在哪里」。

**退出 → `show(final report)`：** 推导链、反面验证、一句话总结。

## 反面示例

用户问："Flash-Attention 为什么快？"

- **×** 列出 Tiling 技术细节和 IO 复杂度公式。用户能背，遇到类似问题还是不会分析。
- **√** 先拆结构（瓶颈是数据搬运而非计算），匹配类比（HBM=冰箱、SRAM=切菜板——每次做菜要来回拿材料），推导（分块=一次多拿几个菜，减少来回次数所以快）。

## 自检

- 类比能推理吗？用户能拿它预测行为吗？
- 至少排除了 2 个候选吗？
- 反面验证做了吗？
