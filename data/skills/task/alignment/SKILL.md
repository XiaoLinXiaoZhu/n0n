# 需求对齐（Alignment）

## 执行步骤

### 1. 提取验收标准

从四个方向拆解用户指令：

- **用户明说**：明确要求的交付物和效果
- **隐含默认**：风格一致、不引入新问题、不破坏已有功能
- **历史共识**：对话历史中确认过的约定，除非用户推翻
- **不可触碰**：哪些操作超出范围、哪些文件不能动

每条目标表述为可验证的断言——「完成后 X 应该能 Y」，不写实现路径。

### 2. 标记不确定性

列出所有模糊点、冲突和需要用户决策的事项：

- 指令之间有冲突？（如「快速做完」vs「要完整测试」）
- 信息不完整？（不知道目标平台、版本、偏好）
- 存在判断调用？（方案 A vs 方案 B，各有取舍）

不确定的事项在此阶段解决——不要等到执行时才发现没对齐。

### 3. 识别风险

标注可能有安全影响、可能破坏已有功能、或信息不足以判断风险的操作。

### 4. 汇报 → 确认

用 `progress(blocked)` 提交对齐报告：

```
【需求对齐】

【目标清单】
1. [目标描述] — 来源: 用户明说 / 隐含默认 / 历史共识
2. ...

【约束边界】
- 不能碰: ...
- 必须保持: ...
- 可以改变: ...

【不确定点】
1. [不确定项] — 选项 A: ... / 选项 B: ... — 建议: ...
2. ...

【风险提示】
- ...

【确认后开始执行】
```

### 5. 确认后进入执行

用户确认或修正后，进入实现阶段。
