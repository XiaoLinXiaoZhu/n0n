# Writing Shape

接收一份原始素材文件，通过对话式塑形产出一篇文章。

## 前置

读取用户提供的原始素材文件（fragments、笔记、草稿、转录）。如果用户没指定输出路径，用 `show(ask user question)` 询问一次。

原始素材文件是只读的——不编辑它。产出写入单独的文章文件。

## 循环

### 1. 产出候选开头

写出 2-3 个候选开头，每个暗示不同的论点或角度。用 `show(ask user question)` 呈现，用户选一个或混合。

选定的开头定义了文章剩余部分的方向。

### 2. 逐段生长

每段回答："given this opening, what does the reader need to hear next?"

从原始素材中拉取内容。素材是矿场不是脚本——可以拆分、重组、改写。

### 3. 争论格式选择

每段的格式不默认使用散文——和用户讨论，给出理由：

| 格式 | 适用场景 |
|------|----------|
| 散文 | 承载论证 |
| 列表 | 平行项（真正平行才用；不平行用散文） |
| 表格 | 同一结构重复 3+ 次 |
| 引用 | 原文措辞本身就是重点 |
| 高亮框 | 会打断主论证的旁注 |
| 代码块 | 多行、可运行、或说明性的代码 |

### 4. 边写边落笔

每段确定后立即 write 追加到文章文件。每次写入前 observe 重读——用户可能已编辑。

### 5. 质检式追问

持续使用以下质检：

- "这段为读者做了什么前一段没做的事？"
- "如果删掉这段，什么会 break？"
- "开头承诺了 X，我们偏到了 Y——重新串联还是改开头？"

### 6. 命名缺口

如果素材缺少文章需要的内容，明确指出："这里需要一个例子，素材中没有——现在给我一个或者砍掉这部分。"

## 完成

文章结束由用户决定。大多数素材堆会有剩余——正常，不必全用完。

**退出 → 提交 `show(final report)`**，包含文章路径和结构概要。
