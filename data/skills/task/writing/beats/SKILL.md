# Writing Beats

将文章写作从"一次性产出"变为"逐 beat 推进的交互式旅程"。

## 什么是 beat

一个 beat 是旅程中的一步——设定场景、落点、提问、插曲、转向。然后停下，让下一个 beat 可以从这里转向。

大小由需要决定：
- 一句话，如果这个 move 只需要一句
- 一短段，如果需要铺垫
- 多段，如果是独立的小故事、论证或例子

如果一个"beat"需要五段和三个小标题——那不是一个 beat，而是两个粘在一起了。拆开。

## 前置

用户提供原始素材文件。如果没指定输出路径，用 `show(ask user question)` 询问一次。

## 循环

### 1. 起始 beat

从原始素材中写出 2-3 个候选起始 beat，每个是不同的入口。用 `show(ask user question)` 呈现，附带每个选项可能导向的后续方向预览。

用户选一个。

### 2. 写入一个 beat

只写被选中的那个 beat 到文章文件。不写下一个。

从素材堆中拉取内容填充 beat——可以改写、拆分、重组。素材是矿场。

### 3. 提供下一步选项

observe 重读文章文件（用户可能已编辑）。然后提供 2-3 个候选下一步 beat，每个是不同的方向。用 `show(ask user question)` 呈现。

### 4. 循环

重复步骤 2-3 直到文章自然结束。

## 行为规则

- **一次只追加一个 beat**——不提前写
- **每次写入前重读文件**——保留用户编辑
- **用户可以回退**——"重写那个 beat"、"回到 beat 3 试另一个方向"都是正常指令
- **素材不必全用完**——文章结束由旅程的完整性决定，不由素材量决定

## 完成

**退出 → 提交 `show(final report)`**，包含文章路径和 beat 列表概要。
