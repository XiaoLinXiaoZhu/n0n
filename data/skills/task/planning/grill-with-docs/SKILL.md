# Grill With Docs

对计划进行穷举式质询，同时维护项目的领域词汇表和架构决策记录（ADR）。

## 核心行为

### 一次一个问题

遍历设计树的每个分支，逐个解决依赖关系。每个问题附上你的推荐答案。等待用户反馈后再继续。

能通过探索代码库回答的问题（observe），不问用户。

### 挑战模糊用语

用户用到与 AGENTS.md 中领域词汇冲突的术语时立即指出。

> "你的词汇表定义'取消'为 X，但你说的似乎是 Y——哪个是对的？"

用户用到模糊或多义词时提出精确的规范术语。

> "你说'账户'——是指 Customer 还是 User？它们是不同的东西。"

### 用具体场景压力测试

讨论领域关系时，发明探测边界情况的具体场景，迫使用户精确定义概念之间的界限。

### 与代码交叉验证

用户说"某个东西是这样工作的"时，observe 检查代码是否一致。发现矛盾就指出来。

## 内联文档维护

### 领域词汇表

术语确定后立即写入 AGENTS.md 的领域词汇部分（或 CONTEXT.md，如果项目有的话）。不攒到最后。词汇表只包含领域语言，不包含实现细节。

### ADR

**只在同时满足三个条件时提供 ADR**：

1. **难以逆转**——改变主意的成本有意义
2. **无上下文会困惑**——未来读者会想"为什么这样做？"
3. **真正的取舍**——有实际的替代方案，你因为具体原因选了这个

缺任何一个条件就跳过 ADR。

## 交互节奏

- 每个问题一个 `show(ask user question)`，呈现问题、推荐答案和备选答案
- 用户回答后 `show(progress report)` 记录决策和依据
- 文档更新（write）在决策确定时立即执行，不等到会话结束
