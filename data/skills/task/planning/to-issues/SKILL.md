# To Issues

将计划拆分为独立可抓取的纵向切片（vertical slice / tracer bullet）issue。

## 流程

### 1. 收集上下文

使用对话中已有的信息。如果用户传入了 issue 编号或路径，读取其完整内容。如果尚未了解代码库，先 observe。

### 2. 拆分纵向切片

**核心原则：纵向切片，不水平分层。**

每个 issue 切穿所有集成层（schema → API → UI → tests），完成后可独立演示或验证。

每个切片标注类型：
- **AFK**——agent 可独立完成，无需人类参与
- **HITL**——需要人类参与（架构决策、设计审查）

优先 AFK，减少人类阻塞点。

### 3. 呈现给用户

用 `progress(blocked)` 呈现拆分方案，每个切片包含：

- **标题**：简短描述
- **类型**：AFK / HITL
- **阻塞关系**：被哪些切片阻塞
- **覆盖的用户故事**：对应源材料中的哪些故事

请用户确认：
- 粒度是否合适？
- 依赖关系是否正确？
- AFK/HITL 分类是否正确？

迭代直到用户批准。

### 4. 发布 issue

按依赖顺序（先发布阻塞方）创建 issue，使用以下模板：

```markdown
## 父任务
（引用父 issue，如有）

## 构建内容
这个纵向切片的端到端行为描述。不写具体文件路径。

## 验收条件
- [ ] 条件 1
- [ ] 条件 2

## 阻塞关系
- 被 #X 阻塞（或"无阻塞，可立即开始"）
```

**退出 → 提交 `progress(completed)`**，包含已创建的 issue 列表和依赖关系图。
