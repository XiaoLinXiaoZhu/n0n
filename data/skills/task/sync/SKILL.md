# 工作归档（Sync）

## 做两件事

1. **进度标注** — 在代码旁边插入 `// TYPE:` 标注
2. **决策文档** — 将重要决策写入独立 spec 文件

## 格式约定

### 进度标注

与 `// TODO:` 同一套格式。标注放在和它相关的代码最近的地方。

```
// TODO: <什么都没做，需要后续实现>
// WIP: <进行中，做到哪了>
// ISSUE: <已知问题/坑，暂不修复>
// FIXME: <需要修复但暂时没修>
```

示例：
```
// WIP: CRUD 完成，权限校验未做，测试只写了 create
// ISSUE: 并发下可能出现重复插入，暂时用唯一索引兜底
```

时间不需要标注——用 `git blame` 追溯。

### 决策文档

在距离相关代码最近的地方写文档：
- **模块级决策**：放在模块目录内（如 `src/user/service/decision-xxx-<hash>.md`）
- **全局级决策**：才放 `docs/decisions/` 下

命名格式：`<主题>-<记录时的git-hash>.md`

```markdown
# [决策标题]
记录版本: <git-hash>
状态: 试验性 / 采纳 / 已废弃（被 [xxx](path) 取代）

## 背景
为什么需要做这个决定

## 决策
选了什么

## 约束
当时的限制条件

## 排除方案
考虑过但不要的，以及为什么不要
```

决策文档只增不改——每个决策对应一个 git hash，版本已固化在文件名中。

## 执行步骤

### 1. 进度标注

扫描指定范围内的代码，识别需要标注的位置（未完成的功能、已知问题、临时方案）。用 `write` 重写文件，在相关代码最近位置插入标注。

不猜测未确认的状态——不确定时用 `show(ask user question)` 询问。

### 2. 决策文档

梳理需要记录的决策点，判断其影响范围：
- **模块级决策**：放在对应模块目录内
- **全局级决策**：放在 `docs/decisions/` 下

获取当前 git hash，用 `write` 创建文档。

### 3. 总结汇报

退出 → `show(final report)`：** 标注清单和决策文档路径。
