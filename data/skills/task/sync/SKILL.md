# 工作归档（Sync）

## 做两件事

1. **进度标注** — 在代码旁边插入 `// TYPE:` 标注
2. **决策文档** — 将重要决策写入独立 spec 文件

## 格式约定

### 进度标注

与 `// TODO:` 同一套格式。标注放在和它相关的代码最近的地方。

```
// TODO: <什么都没做，需要后续实现>
// WIP: <进行中，做到哪了>
// ISSUE: <已知问题/坑，暂不修复>
// FIXME: <需要修复但暂时没修>
```

示例：
```
// WIP: CRUD 完成，权限校验未做，测试只写了 create
// ISSUE: 并发下可能出现重复插入，暂时用唯一索引兜底
```

时间不需要标注——用 `git blame` 追溯。

### 决策文档

独立文件，路径 `docs/decisions/<主题>-<日期>.md`。只增不改。

```markdown
# [决策标题]
日期: YYYY-MM-DD
状态: 试验性 / 采纳 / 已废弃（被 [xxx](path) 取代）

## 背景
为什么需要做这个决定

## 决策
选了什么

## 约束
当时的限制条件

## 排除方案
考虑过但不要的，以及为什么不要
```

## 执行步骤

### 1. 确认范围

用 `progress(blocked)` 确认：只做进度标注、只做决策文档、还是两者都做？关注哪些文件/模块？

### 2. 进度标注

扫描指定范围内的代码，识别需要标注的位置（未完成的功能、已知问题、临时方案）。用 `edit` 在相关代码最近位置插入标注。

不猜测未确认的状态——不确定时用 `progress(blocked)` 询问。

**退出 → `progress(working)`：** 标注清单和数量。

### 3. 决策文档

与用户确认需要记录的决策点。梳理背景、决策、约束、排除方案。用 `write` 创建文档。

**退出 → `progress(completed)`：** 标注清单和决策文档路径。
