# Handoff

将当前对话的隐性知识提取为显性文档，让另一个 agent 可以接续工作。

## 核心原则

**最好的交接物是项目本身。** 优先级链：

1. 代码本身
2. 代码周围的注释
3. 模块入口的注释
4. 文档

文档不应反向被代码引用。handoff 文档只记录"项目本身无法自解释的内容"。

## 流程

### 1. 盘点已有产物

检查本次会话中产生的持久化产物：commit、PRD、issue、ADR、代码注释、TODO。这些已经是交接的一部分——不重复。

### 2. 识别未落地的内容

识别对话中讨论过但尚未落地到代码或文档的内容：

- 进行中的工作上下文（正在做什么、做到哪了）
- 尚未落地的决策（讨论了但还没实现）
- 发现的问题（已知但还没修）
- 方向性判断（为什么选了这条路而不是另一条）

### 3. 撰写交接文档

写入文件（路径由用户指定或使用 `.temp/handoff-<timestamp>.md`）。

```markdown
## 当前状态
（正在做什么、做到哪一步了）

## 已完成的工作
（引用 commit/PR/issue，不复制内容）

## 待完成的工作
（下一步要做什么、按什么顺序）

## 未落地的决策
（讨论了但还没实现的决策，以及原因）

## 已知问题
（发现了但还没修的问题）

## 建议的 skill
（下一个 session 应该加载什么 skill）
```

### 4. 确保代码可自解释

在写交接文档之前，检查代码中是否有该加注释但没加的地方。优先把信息写进代码注释和 TODO，而不是依赖交接文档。

**退出 → 提交 `show(final report)`**，包含交接文档路径和内容概要。
