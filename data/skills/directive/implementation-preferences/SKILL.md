# 运行时实现偏好

本文件只提供条件化实现偏好，不定义生产合格或不合格。客户订单、
Self-Function 标准、系统权限与安全边界、当前工具接口和项目口径优先。
条件不成立或接口事实已经变化时，不应用对应偏好。

## 调用与分轮

后续调用的内容、是否执行和安全检查在看到前序结果前已经确定，且工具接口提供所需顺序或并发语义时，
倾向在同一响应提交调用，减少没有信息价值的往返。

后续动作取决于前序输出、成功状态、客户确认或新的安全判断时，先取得结果再继续。
同一响应提交不表示完成顺序相同；实际顺序、并发和暂停行为以工具接口为准。

## 命令与脚本

- 简单、可直接审查的单个命令倾向直接执行。
- 解析结构化数据、过滤集合、循环处理或生成摘要时，倾向使用适合当前环境的短脚本，
  避免难以审查的多层 shell 拼接。
- 工具提供 runtime 参数时，倾向直接选择已确认可用的运行时，不通过默认 shell 再调用解释器。
- 可能长时间运行的命令，依据项目指令、既有自动化耗时或本轮观察设置等待上限。

## 编辑

当前编辑接口支持范围受限的补丁或文本替换，且目标是需要保护未改区域的既有产物时，
倾向使用可唯一定位的局部修改。不能唯一定位时增加上下文。

生成文件、适合完整重建的短文件、领域专用格式，或只支持完整写入的工具可以采用其他方式。
实际选择以减少误覆盖、遗漏和不可审查差异为目标。

## 检索

确认工具存在后，跨文件文本检索倾向使用 `rg`，JSON 等结构化数据的直接筛选倾向使用 `jq`；
复杂转换、循环或多源合并倾向使用脚本。不可用时选择能产生同等证据的现有工具。

## 版本控制提交信息

订单已授权创建提交，且版本控制工具支持从文件读取提交信息时，倾向先将提交信息写入临时文件，
再由该文件创建提交，避免命令行引号和换行导致截断。

## 试验隔离

第三方库只用于探索或验证、不是订单要求加入项目的正式依赖时，倾向将依赖和产物放入临时目录或独立环境，
不修改主项目依赖、锁文件、共享配置或长期环境。Python 场景中 `uv` 已确认可用且适合时，倾向使用其隔离环境。

正式依赖变更按订单和项目口径处理，不套用试验性隔离偏好。
