# Record — 记录与归档指令

## 标准

### 路径

- 用户指定路径时使用该路径。
- 用户未指定路径时使用当前工作区的 `docs/`。
- 所有引用路径均相对于归档根目录；除非用户明确要求，不要把源文件和归档文件混在一起。

### 信息分层

先按稳定性而非来源格式分类。一个来源可以拆入多个层级。

| 层级 | 判定 | 载体 | 维护规则 |
| --- | --- | --- | --- |
| 静态知识 | 长期有效；不依赖“现在是什么”；变化时代表规则、概念或约定本身改变 | Markdown，按主题组织 | 保存结论、定义、约束、关系和稳定操作方法；不得混入当前值、执行历史或状态快照 |
| 动态事件 | 描述某时刻发生的操作、变化、决策或结果 | `changelog.jsonl` | 每行一个 JSON 对象，只在末尾追加；禁止覆盖、重排或修改历史行；修正历史时追加纠正事件 |
| 动态状态 | 会随时间或环境变化的当前值、清单、进度或外部状态 | 优先从源读取；必须固化时使用独立 JSON 快照 | 不写入静态 Markdown；快照应携带采集时间和来源，并可整体替换或按时间另存 |
| 原始备份 | 需要保留的源文件原貌 | `backup/` 下的原格式文件 | 复制而非移动；文件名包含时间戳，避免覆盖；在动态事件中记录来源和备份路径 |

出现“当前、截至、最新、现状、进行中、剩余、版本为”等依赖时点的表述，默认属于动态内容。若一句话同时包含稳定规则和当前值，必须拆分：例如把“配置由 X 管理”写入静态知识，把“当前值为 Y”写入状态。

### 文件组织

```text
<archive>/
├── <topic>.md          # 静态知识，可按主题拆分
├── changelog.jsonl     # 动态事件，可选
├── state.json          # 动态状态快照，仅在确有必要时创建
└── backup/             # 原始备份，可选
```

- 静态知识按主题组织，不按采集批次堆叠；同一事实只有一个权威位置。
- 动态事件使用稳定字段：`ts`、`event`、`target`、`result`，按需增加 `source`、`note`、`backup`。
- 时间使用带时区的 ISO 8601 格式。
- 可从权威来源即时读取的状态默认不落盘；在静态知识中只记录读取方法和来源位置，不记录读取结果。
- 必须固化历史时刻或来源之后可能消失时才创建快照。快照至少包含 `captured_at`、`source` 和 `data`。

## 动作

### 提取

1. 读取用户提供的来源和已有归档，先理解现有主题、字段和权威位置。
2. 提取原子事实；保留来源、时间语境和不确定性，不把推测写成事实。
3. 对每条事实依次判断：
   - 去掉时间和当前环境后是否仍成立？是则归入静态知识。
   - 它是否描述一次发生过的变化？是则归入动态事件。
   - 它是否描述某时刻的值或状态？是则归入动态状态。
   - 是否必须保留源文件原貌？是则归入原始备份。
4. 同时符合多个类别时拆成多条，分别维护；不要为了保持原文结构而耦合静态知识和动态内容。

### 整理

1. 确定归档根目录并创建所需目录。
2. 将静态知识合并到对应主题 Markdown：
   - 先去重，再更新已经失效的规则。
   - 用陈述事实的方式改写，移除采集过程、当前状态和流水账。
   - 若新信息与旧知识冲突，核对来源；无法裁决时明确标注冲突，不擅自覆盖。
3. 将事件逐条追加到 `changelog.jsonl`，不得整体重写已有文件。
4. 处理动态状态：
   - 能现场读取时，提供可复现的读取命令或脚本，不保存读取结果。
   - 必须固化时，写入独立快照；不得复制进 Markdown。
5. 需要备份时复制到 `backup/`，使用时间戳命名，并追加对应备份事件。

### 维护

- 静态知识变化时直接修订权威 Markdown，并追加一条事件说明变更原因；不要保留已经失效的正文版本充当历史。
- 状态变化只更新状态来源或独立快照，不联动修改静态知识。只有读取方式、字段含义或稳定规则改变时才修改 Markdown。
- 事件历史永不就地修改。错误记录通过新的纠正事件维护，并引用被纠正事件的时间或标识。
- 定期清除静态知识中的时效性内容：将当前值迁移到状态，将操作经过迁移到事件；迁移完成后删除 Markdown 中的重复内容。
- 保持单一事实来源：Markdown 解释稳定知识，JSONL 回答“发生过什么”，状态源或 JSON 回答“现在是什么”，备份保存“当时的原件”。

### 验证与交付

1. 读回所有改动，确认静态 Markdown 不含未隔离的时效性状态。
2. 逐行解析 JSONL，并解析所有 JSON 快照。
3. 确认事件仅追加、备份未覆盖同名文件、原文件未被意外修改。
4. 最终报告归档路径、文件清单、静态与动态内容的拆分方式、验证结果，以及仍存在的冲突或不确定项。
