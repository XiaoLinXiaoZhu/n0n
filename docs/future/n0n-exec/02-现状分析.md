## 数据流（当前）

### 正常完成路径

```
LLM tool_call(observe, { script: "cat file.ts" })
  → toolkit.getEntry("observe").execute(tc)
    → execToolStream(call, confirmFn, execConfig)
      → security.findBlockedCommand()  // 安全检测
      → write temp file (*.sh)
      → runProcess({ spawnCmd, cwd, waitforMs })  // process-runner.ts
        → Bun.spawn(spawnCmd)
        → pumpStream(stdout) + pumpStream(stderr)  // 流泵
        → Promise.race([streamsDone, waitforTimer])  // 超时竞争
        → proc.exited  // 等待退出
        → return { outcome: "completed", stdout, stderr, exitCode }
      → 格式化输出（截断/正常）
      → yield ToolResult
    → renderer 展示
```

### 后台化路径

```
LLM tool_call(observe, { script: "bun run dev", waitfor: 60 })
  → ...（同正常路径，直到 Promise.race）
    → waitforTimer 先触发
    → return { outcome: "backgrounded", pid, stdoutSoFar, ... }
  → startBackgroundSync()  // 后台协程
    → setInterval 定期同步输出到 exec_bg_{pid}.log
    → await proc.exited → 写最终日志
  → yield ToolResult { status: "backgrounded", pid, logFile }
```

## 当前痛点

### P1：后台进程不可管理

agent 启动后台进程后（如 dev server），无法：
- 查看进程是否仍在运行
- 读取进程的后续输出
- 终止进程

当前唯一的途径是用户离开 agent，手动执行 `ps aux | grep ...` 和 `kill <pid>`。

### P2：agent 侧执行逻辑臃肿

`process-runner.ts` 的 Promise.race 超时机制与 `executor.ts` 的后台协程管理加在一起约 350 行，与 agent 核心循环在同一个进程中运行。任何 bug（如流泵死锁）都可能阻塞整个 agent 主循环。

### P3：不可独立测试

测试 `runProcess` 的超时后台化行为需要构造完整的 spawn 环境。当前测试（`packages/tools/src/__tests__/`）通过 mock Bun.spawn 间接测试，覆盖率有限。

### P4：无执行历史

当前每次 exec 调用的产物（临时脚本、输出）在调用结束后立即清理（后台进程除外）。无法回溯"agent 在某轮循环中执行了什么命令、结果是什么"。

### P5：tag-based 重启无原生支持

`bun run dev` 修改代码后需要重启——当前流程是：
1. 用户手动 `kill` 旧进程
2. agent 再次 `act({ script: "bun run dev" })`

每次代码变更都需要这个手动循环。没有"自动替换同 tag 旧进程"的机制。

## 与 n0n-init / n0n-skill 的对比

| 维度 | n0n-init / n0n-skill | 当前 exec | 目标 n0n-exec |
|------|---------------------|----------|---------------|
| 运行模式 | 一次性 CLI，运行→输出→退出 | agent 进程内函数调用 | 一次性 CLI，运行→输出→退出 |
| 状态存储 | 无状态 | 无持久化（后台日志除外） | 文件系统（session dir） |
| 流式输出 | 不需要 | AsyncGenerator 流式 yield | stdout 流式转发 |
| 调用方 | agent（execSync） | agent（函数调用） | agent（Bun.spawn） |
| 独立可测 | 是（终端直接调用） | 否（需 agent 上下文） | 是（终端直接调用） |
