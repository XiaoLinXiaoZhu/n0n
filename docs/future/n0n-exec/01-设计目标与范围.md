# 01 — 设计目标与范围

## 设计目标（Design Objectives）

本方案的设计目标按优先级从高到低排列。

### DO-1：进程生命周期可管理

**当前状态**：agent 通过 observe/reason/act 启动的子进程，在转入后台后 agent 无法查询其状态、无法主动终止。用户需要离开 agent 交互界面，手动使用 `ps` / `kill` 管理这些进程。

**目标状态**：agent 可以列出活跃后台进程、按 PID 或序号查看执行状态和输出、终止指定进程。所有操作通过 n0n-exec 子命令完成。

**度量**：agent 在无需用户手动介入的情况下，可完成"启动 dev server → 查看状态 → 终止"的完整生命周期操作。

### DO-2：简化 agent 侧执行逻辑

**当前状态**：`process-runner.ts`（237 行）和 `executor.ts`（420 行）中包含子进程 spawn、流泵、Promise.race 超时管理、后台协程、日志同步、输出截断等逻辑。这些逻辑与 agent 核心循环耦合在同一进程中。

**目标状态**：agent 侧的 execute() 精简为：spawn n0n-exec → 流式读取 stdout → 等待退出 → 读取 result.json。核心复杂度（超时管理、后台化、日志写入）移入 n0n-exec。

**度量**：agent 侧 execute() 实现不超过 80 行（不含 import 和类型定义）。

### DO-3：独立可测试

**当前状态**：exec 逻辑与 agent loop、renderer、toolkit 注册耦合，无法脱离 agent 单独测试。测试一个超时后台化场景需要启动完整的 agent 循环。

**目标状态**：n0n-exec 可作为独立 CLI 在终端直接调用和测试。`n0n-exec run "sleep 10" --waitfor 2` 可以直接验证超时后台化行为。

**度量**：n0n-exec 的所有子命令可在终端直接调用，输出结果可独立验证。

### DO-4：LLM 工具接口不变

**当前状态**：LLM 可见三个工具——observe、reason、act。各自有独立的描述、waitfor 默认值和工具顺序。

**目标状态**：三个工具的 LLM 接口定义（名称、描述、参数 schema）不变。仅修改其内部实现：从直接调用 execToolStream 改为调用 execute() → spawn n0n-exec。

**度量**：`bun run packages/tools/scripts/preview-tool-definitions.ts` 的输出在变更前后一致。

### DO-5：长期运行进程的自动替换

**目标状态**：通过 `--tag` 参数支持"同 tag 旧进程自动 kill + 新进程启动"的语义。解决"改代码 → 重启 dev server → 手动杀旧进程 → 端口冲突"的循环。

**度量**：`n0n-exec run "bun run dev" --tag "server"` 连续执行两次，第二次自动 kill 第一次的进程后启动。

## 范围界定（Scope）

### 包含

| 项 | 说明 |
|----|------|
| 新建 `packages/exec/` | exec 执行器核心逻辑（库） |
| 新建 `apps/n0n-exec/` | n0n-exec CLI 入口 + 子命令 |
| 修改 `packages/tools/src/exec/` | 替换 executor.ts 实现，改为调用 n0n-exec |
| 修改 `packages/tools/src/index.ts` | 简化 exec 工具注册，注入 session dir |
| 修改 `packages/core/src/runtime.ts` | ToolsConfig 中 tempDir → sessionDir |
| 修改 `apps/code/src/index.ts` | 生成 session ID，创建 session 目录 |
| 新增 session 目录结构 | `.n0n/sessions/session-<id>/exec/` |
| 迁移安全检测到 n0n-exec | `security.ts` 逻辑移入 n0n-exec |
| 文档 | 本目录下的设计文档 |

### 不包含（Non-Goals）

| 项 | 说明 |
|----|------|
| observe/reason/act 合并 | LLM 接口保持不变，三角色继续存在 |
| read/grep/ls 专用工具 | 本次不新增 LLM 可见工具，不修改工具本体论 |
| 格式化外置 | executor 中输出格式化逻辑暂不移入 renderer |
| session 自动清理 | 用户手动删除 session 目录，无自动 GC |
| n0n-exec 守护进程模式 | n0n-exec 始终为无状态 CLI，不常驻 |
| 跨 session 的进程管理 | 所有操作限定在单个 session 内 |
| n0n-exec 的 stdin 接口 | 本次仅通过命令行参数传入脚本，未来可扩展 stdin 模式（见 `docs/future/exec-stdin.md`） |

---

## 设计约束

1. **不修改 LLM 工具接口** — 工具名、描述、参数 schema 保持与当前 `mvp` 分支一致
2. **agent 进程内不再直接 spawn 用户命令** — 所有命令执行统一走 n0n-exec
3. **n0n-exec 不依赖 n0n 的任何包** — 独立编译、独立运行
4. **向后兼容** — 现有测试用例在变更后仍通过（可能需要更新 mock 策略）
