# 00 — 术语定义

> 本文档定义 n0n-exec 方案中使用的所有关键术语。各术语在后续文档中首次出现时不再重复说明。

---

## 核心实体

### n0n-exec

独立的命令行工具（CLI），封装子进程的 spawn、流式输出转发、超时管理、后台化及进程生命周期追踪。以无状态方式运行——每次调用独立启动和退出，状态通过文件系统持久化。

对应的 npm 包为 `@n0n/exec`，CLI 入口为 `apps/n0n-exec`。

### execute()

agent 侧（`@n0n/tools`）的统一执行入口函数。observe / reason / act 三个工具在内部均调用 execute()，execute() 再通过 spawn n0n-exec CLI 完成实际的命令执行。

签名（草案）：

```typescript
async function* execute(args: {
  script: string;
  runtime?: string;
  waitfor?: number;
  tag?: string;
  cwd?: string;
}, config: {
  sessionDir: string;
  blockedCommands: string[];
}): AsyncGenerator<ToolStreamEvent>
```

### ExecRole

observe / reason / act 的角色枚举类型。定义于 `packages/tools/src/exec/role.ts:17`：

```typescript
export type ExecRole = "observe" | "reason" | "act";
```

三个角色共享同一执行后端，差异仅在 LLM 可见的工具描述和 waitfor 默认值。**本次变更不修改 ExecRole 的定义和数量。**

### 会话 (Session)

从 n0n-code 启动到退出的一次完整交互周期。一个会话对应一个 `.n0n/sessions/session-<id>/` 目录。会话 ID 由 n0n-code 在启动时生成（格式：`YYYYMMDD-HHmmss-<random>`）。

### 会话目录 (Session Directory)

会话的文件系统根目录，路径为 `.n0n/sessions/session-<id>/`。其下 `exec/` 子目录存放 n0n-exec 的所有产物。

### 运行 (Run)

一次 execute() 调用（即一次工具调用）对应一个 run。每个 run 有唯一索引号（从 001 递增），产物存放在 `exec/runs/<index>/` 下。

### 运行索引 (Run Index)

run 的序号，三位数字，从 `001` 开始递增。由 n0n-exec 在每次 `run` 子命令调用时自动分配。

## 执行机制

### waitfor

最大等待时间（秒）。命令在 waitfor 内完成则正常返回；超过 waitfor 后 n0n-exec 将进程转入后台，写入后台状态文件后退出。

observe / reason 默认 60s（上限 120s），act 默认 120s（上限 240s）。定义于 `packages/tools/src/exec/definition.ts:36-39`。

### 后台进程 (Backgrounded Process)

因超过 waitfor 而被 n0n-exec 主动放弃等待、但继续在操作系统层面运行的子进程。n0n-exec 退出后，该进程被 init（PID 1）收养。

后台进程的状态通过 `exec/bg-procs/<pid>.json` 追踪。

### tag

用户指定的进程标签（字符串）。用于标识需要反复重启的长期运行进程（如 dev server）。

当 `n0n-exec run --tag <tag>` 时，n0n-exec 会自动查找同 session 下同 tag 的旧后台进程并 kill，然后启动新进程。tag 的作用域限定在单个 session 内。

### 流式输出 (Streaming Output)

子进程的 stdout/stderr 通过 n0n-exec 实时转发到 agent 的 renderer 管线，而非等待进程结束后一次性返回。实现方式：n0n-exec 将子进程输出写入自己的 stdout，agent 通过 `Bun.spawn` 的 stdout stream 读取。

## 文件系统

### exec 目录结构

```
.n0n/sessions/session-<id>/exec/
  runs/                # 所有 run 的产物
    001/               # 第 1 次 run
      command.txt      # 原始命令脚本
      stdout.txt       # 完整 stdout
      stderr.txt       # 完整 stderr
      result.json      # 结构化结果
      meta.txt         # 人类可读摘要
    002/
      ...
  bg-procs/            # 活跃后台进程
    <pid>.json         # { pid, tag, runIndex, startedAt }
  tags/                # tag → pid 映射
    <tag>.json         # { pid, runIndex }
```

### result.json 格式

```typescript
interface RunResult {
  status: "completed" | "backgrounded" | "error";
  exitCode: number | null;
  durationMs: number;
  pid: number;
  // status === "backgrounded" 时额外字段：
  logFile?: string;
  // status === "error" 时额外字段：
  error?: string;
}
```

### bg-procs/<pid>.json 格式

```typescript
interface BgProcInfo {
  pid: number;
  tag: string | null;
  runIndex: number;
  startedAt: string;  // ISO 8601
}
```

## 子命令

| 子命令 | 功能 |
|--------|------|
| `run` | 执行脚本，等价于当前的 exec 工具 |
| `list` | 列出当前 session 下所有活跃后台进程 |
| `status` | 按 PID 或 run index 查看执行状态和输出 |
| `kill` | 终止指定后台进程 |
| `history` | 列出当前 session 的历史执行记录 |

## 安全

### blocked_commands

禁止执行的命令名列表。通过环境变量 `N0N_BLOCKED_COMMANDS`（逗号分隔）传入 n0n-exec。检测逻辑从当前 `packages/tools/src/exec/security.ts` 迁移到 n0n-exec 内部。

### 安全检测时机

在子进程 spawn 之前，n0n-exec 扫描脚本内容中的命令名，与 blocked_commands 比对。命中时拒绝执行并返回错误结果。
