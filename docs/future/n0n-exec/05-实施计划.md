## 测试策略

### 单元测试（`packages/exec/src/__tests__/`）

使用真实的子进程（短命令如 `echo`、`sleep 1`）测试，不 mock Bun.spawn。确保行为与操作系统一致。

### 集成测试（`apps/n0n-exec/` 手动 + 脚本）

编写 shell 脚本验证 n0n-exec 各子命令的端到端行为：

```bash
#!/bin/bash
# 集成测试：n0n-exec run + list + status + kill
export N0N_SESSION_DIR=$(mktemp -d)

# test run
n0n-exec run --script "echo hello"
assert_eq $? 0

# test backgrounding
n0n-exec run --script "sleep 30" --waitfor 1 &
sleep 2
n0n-exec list | grep -q "sleep"
assert_eq $? 0

# test kill
PID=$(n0n-exec list --json | jq -r '.[0].pid')
n0n-exec kill pid $PID
sleep 1
n0n-exec list --json | jq -e 'length == 0'
assert_eq $? 0

# test tag
n0n-exec run --script "sleep 30" --tag "test-srv" --waitfor 1
n0n-exec run --script "sleep 30" --tag "test-srv" --waitfor 1
# 验证只有一个 test-srv 进程
COUNT=$(n0n-exec list --json | jq '[.[] | select(.tag == "test-srv")] | length')
assert_eq $COUNT 1

rm -rf $N0N_SESSION_DIR
echo "All integration tests passed."
```

### 回归测试（`packages/tools/src/__tests__/`）

现有 `exec-*.test.ts` 文件需要更新 mock 策略：mock `Bun.spawn` 的调用目标从用户命令改为 `n0n-exec`。或改为集成测试（真实 spawn n0n-exec）。

## 风险与回滚

### 回滚策略

所有变更在独立分支 `feat/n0n-exec` 上进行。阶段 1 和阶段 2 分别提交。

若阶段 2 出现问题，可回退到阶段 1（n0n-exec CLI 独立可用，但不影响 agent）。若需完全回滚，`mvp` 分支保持当前的进程内执行架构。

### 关键风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| n0n-exec 进程启动开销影响高频调用（如 `cat` 小文件） | 中 | 阶段 3 考虑为简单读操作添加 agent 内快速路径；阶段 1 先测量实际开销 |
| 现有测试大量依赖 mock Bun.spawn | 高 | 阶段 2 将测试改为集成测试风格，或更新 mock 目标 |
| n0n-exec 在不同平台（Windows）的兼容性 | 中 | 阶段 1 在 macOS 上开发和验证；Windows 兼容性留待后续 |
