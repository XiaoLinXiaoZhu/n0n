# 03 — 方案设计

## 整体架构

```
┌─────────────────────────────────────────────────────────┐
│ n0n-code (agent)                                        │
│                                                         │
│  ┌──────────────────────────────────────────────────┐  │
│  │ @n0n/tools                                        │  │
│  │                                                    │  │
│  │  observe ─┐                                       │  │
│  │  reason  ─┼─→ execute() ─→ spawn n0n-exec ─┐     │  │
│  │  act     ─┘                               │     │  │
│  └─────────────────────────────────────────────│─────┘  │
│                                                 │        │
│  ┌──────────────────────────────────────────────│─────┐ │
│  │ renderer ← stdout stream (real-time)         │     │ │
│  └──────────────────────────────────────────────│─────┘ │
└─────────────────────────────────────────────────│───────┘
                                                   │
                  ┌────────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────────────┐
│ n0n-exec (独立进程，无状态 CLI)                          │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────┐  │
│  │ security │  │ spawn    │  │ waitfor / background  │  │
│  │ check    │→ │ command  │→ │ management            │  │
│  └──────────┘  └──────────┘  └──────────────────────┘  │
│                                      │                   │
│                     ┌────────────────┴──────────────┐   │
│                     ▼                               ▼   │
│              completed                         backgrounded
│              (正常返回)                        (写状态后退出)
│                                                     │   │
│              ┌──────────────────────────────────────┘   │
│              ▼                                          │
│         session dir (文件系统)                           │
│         .n0n/sessions/session-<id>/exec/               │
└─────────────────────────────────────────────────────────┘
```

关键设计决策：

1. **n0n-exec 是无状态 CLI**：每次调用独立启动和退出。子命令 `list` / `status` / `kill` / `history` 通过读写 session dir 下的文件获取状态，不依赖内存中的进程表。

2. **agent 不再直接 spawn 用户命令**：所有命令执行统一走 n0n-exec。agent 的 execute() 只需管理 n0n-exec 子进程（读取其 stdout，等待其退出），不再管理用户命令的子进程。

3. **流式输出通过 stdout 转发**：n0n-exec 将用户命令的 stdout/stderr 实时写入自己的 stdout/stderr，agent 通过 Bun.spawn 的 stream 读取，保持当前的实时渲染体验。

## n0n-exec CLI 设计

### 通用约定

- 所有子命令通过环境变量 `N0N_SESSION_DIR` 定位 session 目录
- 安全配置通过 `N0N_BLOCKED_COMMANDS` 环境变量传入（逗号分隔）
- 结构化结果写入 session dir 下的指定文件，同时输出人类可读摘要到 stdout

### run — 执行脚本

```
n0n-exec run [--runtime <rt>] [--waitfor <s>] [--tag <tag>] [--cwd <dir>]
             --script <script_content>
```

**参数：**

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `--runtime` | 否 | sh (Linux/macOS) / cmd (Windows) | 执行运行时 |
| `--waitfor` | 否 | 60 | 最大等待秒数（上限 240） |
| `--tag` | 否 | — | 进程标签。指定时自动 kill 同 tag 旧进程 |
| `--cwd` | 否 | workspace root | 工作目录 |
| `--script` | 是 | — | 要执行的脚本内容 |

**行为流程：**

```
1. 读取 N0N_SESSION_DIR 环境变量
2. 安全检测：扫描 --script 中的命令名 vs N0N_BLOCKED_COMMANDS
   → 命中：输出错误结果，exit 1
3. 若指定 --tag：
   读取 <session>/exec/tags/<tag>.json
   → 若存在且进程存活：kill 该进程
   → 清理 bg-procs/<pid>.json 和 tags/<tag>.json
4. 分配 run index（读取 runs/ 目录下最大序号 +1）
5. 创建 runs/<index>/ 目录
6. 写入 command.txt（脚本内容）
7. spawn 子进程（根据 --runtime 构造 spawn 命令）
8. 流式转发 stdout/stderr 到 n0n-exec 的 stdout/stderr
9. 并行启动 waitfor 计时器
10a. 若命令在 waitfor 内完成：
    写入 stdout.txt, stderr.txt, result.json, meta.txt
    以命令的 exit code 退出
10b. 若超过 waitfor：
    写入 bg-procs/<pid>.json
    若指定 --tag：写入 tags/<tag>.json
    写入 result.json（status: "backgrounded"）
    n0n-exec 退出（exit 0），命令继续在后台运行
```

**结构化输出文件（result.json）：**

```json
{
  "status": "completed",
  "exitCode": 0,
  "durationMs": 1234,
  "pid": 29184,
  "runIndex": 3,
  "stdoutFile": "stdout.txt",
  "stderrFile": "stderr.txt"
}
```

或（后台化）：

```json
{
  "status": "backgrounded",
  "exitCode": null,
  "durationMs": 60001,
  "pid": 29184,
  "runIndex": 3,
  "tag": "server"
}
```

### list — 列出活跃后台进程

```
n0n-exec list [--json]
```

读取 `<session>/exec/bg-procs/` 下所有 JSON 文件，检查对应 PID 是否存活，输出存活进程列表。

`--json` 时输出 JSON 数组，否则输出人类可读表格。

### status — 查看执行状态

```
n0n-exec status pid <pid>
n0n-exec status index <runIndex>
```

读取 session dir 下对应的 result.json，输出执行状态。若进程仍在后台运行，额外输出当前 stdout/stderr 的快照。

### kill — 终止后台进程

```
n0n-exec kill pid <pid>
n0n-exec kill tag <tag>
```

向指定 PID 发送 SIGTERM（可配置为 SIGKILL），清理 bg-procs 和 tags 目录下的对应文件。

### history — 执行历史

```
n0n-exec history [--last <n>] [--json]
```

列出 runs/ 目录下所有 run 的摘要信息（序号、命令首行、状态、耗时）。按时间倒序。

## execute() 接口设计

agent 侧的 execute() 函数签名：

```typescript
import type { ToolStreamEvent } from "@n0n/types";

export interface ExecuteArgs {
  script: string;
  runtime?: string;    // 默认: platform === "win32" ? "cmd" : "sh"
  cwd?: string;        // 默认: workspace root
  waitfor?: number;    // 默认: 取决于 role (observe/reason: 60, act: 120)
  tag?: string;        // 可选进程标签
}

export interface ExecuteConfig {
  sessionDir: string;           // .n0n/sessions/session-<id>/
  blockedCommands: string[];    // 从 security config 传入
  defaultWaitfor: number;       // 从 agent config 传入
  platform: "win32" | "darwin" | "linux";
}

export async function* execute(
  args: ExecuteArgs,
  config: ExecuteConfig,
): AsyncGenerator<ToolStreamEvent>;
```

**实现要点（~60 行）：**

```typescript
export async function* execute(
  args: ExecuteArgs,
  config: ExecuteConfig,
): AsyncGenerator<ToolStreamEvent> {
  const { sessionDir, blockedCommands, platform } = config;
  const runtime = args.runtime ?? (platform === "win32" ? "cmd" : "sh");
  const waitfor = args.waitfor ?? config.defaultWaitfor;

  // 构造 n0n-exec 参数
  const spawnArgs = [
    "n0n-exec", "run",
    "--runtime", runtime,
    "--waitfor", String(Math.min(waitfor, 240)),
    "--script", args.script,
  ];
  if (args.tag) spawnArgs.push("--tag", args.tag);
  if (args.cwd) spawnArgs.push("--cwd", args.cwd);

  // spawn n0n-exec
  const proc = Bun.spawn(spawnArgs, {
    stdout: "pipe",
    stderr: "pipe",
    env: {
      ...process.env,
      N0N_SESSION_DIR: sessionDir,
      N0N_BLOCKED_COMMANDS: blockedCommands.join(","),
    },
  });

  // 流式转发 stdout（实时渲染）
  const decoder = new TextDecoder();
  const stdoutReader = proc.stdout.getReader();
  try {
    while (true) {
      const { done, value } = await stdoutReader.read();
      if (done) break;
      yield {
        type: "tool_output_chunk",
        callId: "...",  // 由调用方注入
        tool: "...",    // 由调用方注入
        chunk: decoder.decode(value, { stream: true }),
      };
    }
  } finally {
    stdoutReader.releaseLock();
  }

  // 等待 n0n-exec 退出
  const exitCode = await proc.exited;

  // 读取结构化结果
  // n0n-exec 退出前在 session dir 下写入了 result.json
  // 通过读取最近的 runs/ 目录获取结果
  const result = await readLatestResult(sessionDir);

  yield {
    type: "tool_result",
    tool: "...",
    call: { ... },
    status: result.status,
    // ... 根据 status 展开字段
  };
}
```

## 会话生命周期

### 创建

n0n-code 启动时（`apps/code/src/index.ts`），在 `resolveBasePaths` 后创建 session 目录：

```typescript
const sessionId = `${new Date().toISOString().replace(/[:.]/g, "-")}-${Math.random().toString(36).slice(2, 8)}`;
const sessionDir = resolve(paths.temp, `session-${sessionId}`);
mkdirSync(sessionDir, { recursive: true });
mkdirSync(resolve(sessionDir, "exec", "runs"), { recursive: true });
mkdirSync(resolve(sessionDir, "exec", "bg-procs"), { recursive: true });
mkdirSync(resolve(sessionDir, "exec", "tags"), { recursive: true });
```

`sessionDir` 通过 `ToolsConfig` 传入 `@n0n/tools`。

### 使用

每次 execute() 调用时，`sessionDir` 作为配置传入，n0n-exec 通过 `N0N_SESSION_DIR` 环境变量接收。

### 销毁

用户手动删除 `.n0n/sessions/session-<id>/` 目录。n0n-code 退出时不自动清理——保留现场供事后分析。

## 安全检测迁移

当前 `packages/tools/src/exec/security.ts`（96 行）的三个函数：

| 函数 | 迁移方式 |
|------|---------|
| `extractCommandNames()` | 移入 n0n-exec 内部 |
| `findBlockedCommand()` | 移入 n0n-exec 内部 |
| `handleBlockedCommand()` | 移入 n0n-exec 内部，用户确认逻辑由 n0n-exec 通过 exit code 2 表示"需要确认"，agent 侧的 execute() 捕获后调用 confirmFn |

**用户确认流程**：当 n0n-exec 检测到 blocked command 时：
1. n0n-exec 输出错误信息到 stderr，以 exit code 2 退出
2. agent 的 execute() 检测到 exit code 2，调用 confirmFn 向用户确认
3. 若用户确认，execute() 重新调用 n0n-exec 并附加 `--force` 标志
4. n0n-exec 收到 `--force` 时跳过安全检测

这样安全策略执行在 n0n-exec 内部（不可绕过），但确认交互保留在 agent 侧（保持用户界面一致性）。

## 输出格式化

当前 executor.ts 中的输出截断逻辑（约 80 行，`TRUNCATION_THRESHOLD_TOKENS = 5000`、`TAIL_TOKENS = 2000`）**暂不移入 n0n-exec**。

理由：
- 截断阈值是 agent/renderer 层面的策略（"renderer 能展示多少内容"），不是执行器的职责
- 不同 app（REPL vs headless）可能有不同的截断策略
- 保持本次变更面窄

n0n-exec 始终写入完整的 stdout/stderr 到 session dir 文件。agent 侧的 execute() 读取文件后按需截断。这是阶段 3 的可选项。

## 依赖关系

```
@n0n/exec (packages/exec)        # 库：spawn、流泵、安全检测
  ↓
n0n-exec (apps/n0n-exec)         # CLI：子命令入口
  ↓ (通过 Bun.spawn)
@n0n/tools (packages/tools)      # execute() 函数
  ↓
n0n-code (apps/code)             # agent 主程序
```

`@n0n/exec` 是纯库，`n0n-exec` 是它的 CLI 包装。agent 通过 spawn `n0n-exec` CLI 来执行命令，不直接引用 `@n0n/exec` 库（保持进程隔离）。
