# 04 — DFMEA（设计失效模式与影响分析）

## 评分标度

### 严重度 (Severity, S)

| 分值 | 描述 | 判定标准 |
|------|------|---------|
| 1 | 几乎无影响 | 用户不可感知 |
| 4 | 轻微影响 | 有 workaround，不影响核心流程 |
| 7 | 严重影响 | 核心流程受阻，无简单 workaround |
| 10 | 系统不可用 | agent 无法执行命令 |

### 发生度 (Occurrence, O)

| 分值 | 描述 | 判定标准 |
|------|------|---------|
| 1 | 几乎不发生 | 需要多重条件同时满足 |
| 4 | 偶尔发生 | 特定场景可触发 |
| 7 | 经常发生 | 常规使用中可触发 |
| 10 | 每次触发 | 每次调用都发生 |

### 检测度 (Detection, D)

| 分值 | 描述 | 判定标准 |
|------|------|---------|
| 1 | 设计期可发现 | 方案评审阶段即可识别 |
| 4 | 开发期可发现 | 实现或单元测试阶段可识别 |
| 7 | 集成测试可发现 | 需要端到端测试才能暴露 |
| 10 | 生产环境才暴露 | 用户使用后才发现 |

### RPN 评估

| RPN | 风险等级 | 行动要求 |
|-----|---------|---------|
| ≥ 200 | 严重 | 必须修改设计，不可接受 |
| 100–199 | 高 | 需要缓解措施，跟踪到关闭 |
| 50–99 | 中 | 评估缓解成本，酌情处理 |
| < 50 | 低 | 可接受，记录即可 |

## 失效模式

### FM-01：n0n-exec 未安装或不可用

| 项目 | 内容 |
|------|------|
| **失效描述** | 用户的 PATH 中不存在 `n0n-exec` 命令。agent 首次 execute() 调用时 spawn 失败。 |
| **影响** | agent 完全无法执行任何命令（observe/reason/act 全部失效）。 |
| **S** | 10 |
| **O** | 4（CI/发布流程可确保安装，但手动开发环境可能遗漏） |
| **D** | 2（agent 启动时即可检测） |
| **RPN** | **80**（中） |
| **缓解措施** | n0n-code 启动时检查 `which n0n-exec` 或 `n0n-exec --version`。不可用时给出明确安装指引（`bun install` 或 `npm install -g @n0n/exec`）。 |
| **残留 RPN** | 16（启动时检测 → O 降至 2, D 降至 1） |

---

### FM-02：n0n-exec 崩溃导致 execute() 挂起

| 项目 | 内容 |
|------|------|
| **失效描述** | n0n-exec 进程异常退出（如 OOM、segfault、uncaught exception），导致 agent 侧的 execute() 在 `await proc.exited` 上永久等待或读取损坏的 result.json。 |
| **影响** | 当前工具调用挂起，agent 主循环停滞。用户需要手动 Ctrl+Q 中断。 |
| **S** | 7 |
| **O** | 3（n0n-exec 逻辑简单，崩溃概率低） |
| **D** | 4（单元测试可覆盖大部分路径） |
| **RPN** | **84**（中） |
| **缓解措施** | 1) agent 侧对 n0n-exec 进程加整体超时（如 waitfor + 30s 硬上限）；2) n0n-exec 内部 try/catch 所有异常路径，确保始终写入 result.json（即使 status: "error"）；3) agent 侧读取 result.json 时处理文件不存在的情况。 |
| **残留 RPN** | 28（整体超时 → O 降至 2, D 降至 2） |

---

### FM-03：session 目录并发写入冲突

| 项目 | 内容 |
|------|------|
| **失效描述** | agent 的 scheduler 允许并行工具调用时，两个 execute() 同时 spawn n0n-exec，两个 n0n-exec 进程同时分配 run index 或写入 bg-procs 文件。 |
| **影响** | run index 重复或跳号；tag 映射文件被覆盖；最坏情况：result.json 损坏。 |
| **S** | 5（不影响命令执行本身，但状态记录错乱） |
| **O** | 2（当前 scheduler 以串行调度为主，并行 exec 场景极少） |
| **D** | 5（并发 bug 难以在单线程测试中暴露） |
| **RPN** | **50**（中） |
| **缓解措施** | n0n-exec 在分配 run index 时使用原子操作（如 `mkdir` 作为文件系统级锁——`mkdir runs/003` 是原子操作，失败则递增重试）。bg-procs 写入使用 PID 作为文件名天然去重。 |
| **残留 RPN** | 20（原子分配 → O 降至 1, D 降至 4） |

---

### FM-04：安全检测绕过

| 项目 | 内容 |
|------|------|
| **失效描述** | 用户通过 `--force` 标志或环境变量操纵绕过 blocked_commands 检测。或 n0n-exec 中的命令提取逻辑（`extractCommandNames`）未覆盖新的 shell 语法（如 here-strings、process substitution）。 |
| **影响** | 被 blocked_commands 列入的命令被执行。 |
| **S** | 8 |
| **O** | 3（`--force` 仅在 agent 确认后传递，常规路径不可用） |
| **D** | 6（需要针对新 shell 语法的专门测试） |
| **RPN** | **144**（高） |
| **缓解措施** | 1) `--force` 不接受环境变量设置，仅接受显式命令行参数；2) 在 blocked_commands 检测之上增加第二层防护：n0n-exec 以非 root 用户运行；3) 定期审计命令提取逻辑与常见 shell 的兼容性。 |
| **残留 RPN** | 48（环境变量 + 权限限制 → O 降至 2, D 降至 3） |

---

### FM-05：后台进程孤儿化后无法追踪

| 项目 | 内容 |
|------|------|
| **失效描述** | n0n-exec 将进程转入后台后写入 bg-procs/<pid>.json 然后退出。若此时操作系统回收了该 PID（进程异常退出），或被 init 收养后进程状态变化，后续 `n0n-exec status pid <pid>` 报告的信息可能过时或不准确。 |
| **影响** | agent 以为进程在运行，实际上已退出。`n0n-exec kill` 可能向已重用的 PID 发送信号。 |
| **S** | 7（误杀风险） |
| **O** | 3（PID 重用需要进程退出 + 新进程恰好分配到相同 PID） |
| **D** | 5 |
| **RPN** | **105**（高） |
| **缓解措施** | 1) bg-procs/<pid>.json 记录进程启动时间（`startedAt`），kill 前校验 `/proc/<pid>/stat` 中的启动时间是否匹配；2) `n0n-exec list` 输出中标注"无法确认存活"的进程；3) 提供 `n0n-exec list --verify` 主动检查每个 PID 的存活状态和启动时间匹配。 |
| **残留 RPN** | 42（时间戳校验 → O 降至 2, D 降至 3） |

---

### FM-06：流式输出截断或乱序

| 项目 | 内容 |
|------|------|
| **失效描述** | n0n-exec 转发子进程 stdout 到自己的 stdout 时，若子进程 stdout 和 stderr 的读取顺序与写入顺序不一致，agent 侧看到的输出可能乱序。或 n0n-exec 退出时 stdout buffer 尚有未刷新数据。 |
| **影响** | agent 和用户看到的命令输出不完全或不正确。 |
| **S** | 5 |
| **O** | 4（Bun.spawn 管道默认无缓冲，但 stderr 与 stdout 交织是经典的并发写入问题） |
| **D** | 4（单元测试可覆盖基本场景） |
| **RPN** | **80**（中） |
| **缓解措施** | 1) n0n-exec 将 stdout 和 stderr 合并到同一个输出流（`stderr: "pipe"` 但转发到 n0n-exec 的 stdout），保证时序；2) n0n-exec 退出前显式 drain 所有 pipe；3) 若需要区分 stdout/stderr，可在每行前加前缀标记（如 `[out]` / `[err]`），由 renderer 解析。 |
| **残留 RPN** | 24（合并流 + drain → O 降至 2, D 降至 3） |

---

### FM-07：session 目录路径过长

| 项目 | 内容 |
|------|------|
| **失效描述** | session ID 包含时间戳和随机串，workspace 路径本身可能很长，导致完整路径超过文件系统限制（Linux: 4096 字节, macOS: 1024 字节）。 |
| **影响** | n0n-exec 无法创建 session 目录下的文件，命令执行失败。 |
| **S** | 6 |
| **O** | 2（需要极深的 workspace 路径 + 长 session ID 同时满足） |
| **D** | 2（开发期使用长路径测试即可发现） |
| **RPN** | **24**（低） |
| **缓解措施** | session ID 长度控制在 32 字符以内（当前格式约 27 字符）。workspace 路径过长时在启动时给出警告。 |

## RPN 排序与缓解后评估

| 排名 | FM | 失效模式 | 原始 RPN | 缓解后 RPN | 风险等级 |
|------|-----|---------|----------|-----------|---------|
| 1 | FM-04 | 安全检测绕过 | 144 | 48 | 低 |
| 2 | FM-05 | 后台进程孤儿化 | 105 | 42 | 低 |
| 3 | FM-02 | n0n-exec 崩溃挂起 | 84 | 28 | 低 |
| 4 | FM-01 | n0n-exec 未安装 | 80 | 16 | 低 |
| 5 | FM-06 | 流式输出乱序 | 80 | 24 | 低 |
| 6 | FM-03 | session 并发写入 | 50 | 20 | 低 |
| 7 | FM-07 | 路径过长 | 24 | 24 | 低 |

**结论：所有失效模式在应用缓解措施后 RPN < 50，无阻塞性风险。**
