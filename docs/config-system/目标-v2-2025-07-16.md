# 配置系统重构 — 目标与架构

版本 2，2025-07-16

## 目标

将 n0n 配置从环境变量前缀切换（`N0N_PREFIX`）重构为基于 TOML + zod schema 驱动的配置系统。

## 架构决定

### 模块位置

`packages/config`，workspace 包，依赖 `smol-toml` + `zod`。

### 设计原则

1. **schema 驱动** — config 模块接受 zod schema，机械地将 TOML 解析为 schema 描述的形状。不关心字段的业务含义。
2. **parse, don't verify** — 输入时收窄为判别类型。错误用可辨联合返回，不抛异常。
3. **纯函数 + 单一 I/O 入口** — 内部全部纯函数，`getConfig()` 是唯一带副作用的入口（调用 smol-toml 解析 + zod 验证）。
4. **config 与 apps 解耦** — config 只做机械类型收窄。连通性测试、交互式创建均在 apps 层。
5. **来源可追踪** — 成功时输出 trace，记录每个字段来自哪个 ConfigSource。

### API

```typescript
interface ConfigSource {
  name: string;      // 用于错误消息和 trace（如 "全局"、"项目"）
  content: string;   // TOML 文本
}

type ConfigResult<T> =
  | { success: true; data: T; trace: Record<string, { value: unknown; source: string }> }
  | { success: false; errors: ConfigError[] };

function getConfig<T>(
  schema: z.ZodType<T>,
  sources: ConfigSource[],
  envPool?: Record<string, string>,
): ConfigResult<T>;
```

### 处理流程

```
sources[] ─→ TOML parse（保持来源标注）
  ↓ deep merge（后者覆盖，来源随之更新）
merged JSON
  ↓ walk: string 值 $ 开头 → envPool 替换（来源不变）
$VAR resolved
  ↓ walk: 含 extend 字段的 object → { ...target, ...own }，递归，环检测（来源随值传递）
extend resolved
  ↓ zod schema.parse()（default 值标注来源 "默认"）
T（类型安全输出）+ trace
```

### 核心机制

- **多文件合并** — `sources` 数组按顺序解析为 JSON，后者深度覆盖前者。
- **`$VAR`** — 字符串值匹配 `/^\$[A-Z_][A-Z0-9_]*$/` 时从 envPool 查找。找不到报错。
- **`extend`** — 保留字段。值为 dot-path 字符串（如 `"providers.anthropic"`）。解析时替换为 `{ ...resolve(path), ...ownFields }`，然后移除 `extend` 键。递归解析，环检测。
- **zod 验证** — 解析完成后的 JSON 对象传入 `schema.parse()`。zod 的 `.default()` 提供回退值。

### 来源追踪（trace）

- TOML 解析时每个叶子值标注 ConfigSource.name
- 合并时后者覆盖，来源随之更新
- $VAR 解析保持原来源
- extend 时来自目标的字段继承目标的来源，自身覆盖字段保持自身来源
- zod default 标注为 `"默认"`

输出扁平 dot-path 映射：`"settings.llm.model" → { value: "...", source: "全局" }`

## 文件布局

```
packages/config/
  package.json
  src/
    types.ts    — ConfigSource、ConfigError（可辨联合）、ConfigResult、Trace
    index.ts    — getConfig() + 内部纯函数（merge、resolveVars、resolveExtends、flattenTrace）
```

## 约定

顶层 key 约定为 `settings`（因为 TOML 的 `[settings]` section），但 config 模块不强加此约束——由 zod schema 自行定义期望形状。

## 使用示例

```typescript
import { getConfig } from "@n0n/config";
import { z } from "zod";

const schema = z.object({
  settings: z.object({
    strip_hint: z.boolean().default(true),
    notify_sound: z.boolean().default(false),
    llm: z.object({
      type: z.string(),
      api_key: z.string(),
      model: z.string(),
    }),
    editor: z.object({
      type: z.string(),
      api_key: z.string(),
      model: z.string(),
    }),
  }),
});

const result = getConfig(schema, [
  { name: "全局", content: globalToml },
  { name: "项目", content: projectToml },
], envPool);

if (result.success) {
  console.log(result.trace);
  // { "settings.llm.model": { value: "claude-opus-4-6", source: "全局" }, ... }
}
```
