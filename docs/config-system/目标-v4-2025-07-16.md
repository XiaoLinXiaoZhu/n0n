# 配置系统重构 — 目标与架构

版本 4，2025-07-16

## 目标

将 n0n 配置从环境变量前缀切换重构为基于 TOML + zod schema 驱动的配置系统。

新模块 `packages/config` 是一个**通用的 TOML 配置加载器**——不包含业务领域知识，只做机械的类型收窄。

---

## API

```typescript
interface ConfigSource {
  name: string;      // 来源名称（"默认"、"全局"、"项目"），用于 trace
  content: string;   // TOML 文本
}

type ConfigResult<T> =
  | { success: true; data: T; trace: Record<string, { value: unknown; source: string }> }
  | { success: false; errors: ConfigError[] };

function getConfig<T>(
  schema: z.ZodType<T>,
  sources: ConfigSource[],
  envPool?: Record<string, string>,
): ConfigResult<T>;
```

---

## 处理流程

```
sources[0].content → TOML parse
sources[1].content → TOML parse
...
  ↓ deep merge（后者深度覆盖前者，来源注释随之更新）
merged JSON
  ↓ walk: 所有 string 值 → 匹配 /^\$[A-Z_][A-Z0-9_]*$/ → 从 envPool 替换
$VAR resolved
  ↓ walk: 含 extend 字段的 object → 递归展开 { ...target, ...ownFields }
extend resolved
  ↓ zod schema.parse()
T（类型安全输出） + trace（dot-path → {value, source}）
```

---

## 核心机制

| 机制 | 行为 |
|------|------|
| **多文件合并** | sources 数组顺序解析为 JSON，后者深度覆盖前者。同级 section 深度合并，标量值替换 |
| **`$VAR`** | 字符串值匹配 `/^\$[A-Z_][A-Z0-9_]*$/` 时从 envPool 查找。未找到→ `env_var_not_found` 错误。`$` 后非大写字母不触发替换 |
| **`extend`** | 保留字段，值为 dot-path 字符串。解析时替换为 `{ ...resolve(target), ...ownFields }`（own 覆盖 target），然后移除 `extend` key。链式递归，环检测 |
| **zod 验证** | extend 解析后的 JSON 传入 `schema.parse()`。额外字段被忽略（zod 默认行为） |
| **trace** | 每个叶子值的最终来源记录在 trace 中。来源按合并/覆盖顺序传递：默认 → 全局 → 项目，extend 目标的来源继承到引用方 |

## 错误类型（可辨联合）

| kind | 说明 |
|------|------|
| `toml_parse_error` | TOML 语法无效 |
| `env_var_not_found` | `$VAR` 引用的环境变量不存在 |
| `extend_target_not_found` | extend dot-path 目标不存在或不是 object |
| `circular_extend` | extend 链存在循环 |
| `schema_validation_error` | zod parse 失败 |

## ProviderConfig 设计

### 单套 schema，不做命名风格转换

ProviderConfig 是 discriminated union on `provider`，字段名与 API 请求体一致（snake_case）。Client 代码直接从 ProviderConfig 赋值到请求体，无需映射层。

```typescript
// TOML → ProviderConfig → API request，字段名 1:1
api_key: z.string()           // TOML api_key → pc.api_key → headers
base_url: z.string().default("https://api.anthropic.com")  // TOML 可省略 → parse 填默认值
enable_thinking: z.boolean().default(false)
reasoning_effort: z.enum(["low", "medium", "high"]).default("high")
thinking: z.object({ type: z.literal("enabled"), budget_tokens: z.number() }).optional()
```

### 各 variant 自包含

不共享 base schema，因为不同 provider 的同名字段语义不同：
- `base_url` 在 openai-compatible 是必填（代理必须指定地址），在其他 variant 有 `.default()`
- `tag_style` 在 DeepSeek 默认 `"deepseek"`，其他默认 `"default"`

### parse, don't verify

有默认回退的字段在 parse 时填入默认值，消费方拿到的类型不含 optional：

| 字段 | 默认值 | 原则 |
|------|--------|------|
| `base_url` | provider-specific | 不提供 = 用 provider 默认地址，语义相同 → default |
| `tag_style` | `"default"`（DeepSeek: `"deepseek"`） | 不提供 = 用默认标签风格 → default |
| `edit_backend` | `"str-replace"` | 不提供 = str-replace → default |
| `enable_thinking` | `false` | 不提供 = 不启用 → default |
| `reasoning_effort` (Google) | `"high"` | 不提供 = high → default |
| `backend_provider` | `"openai"` | 不提供 = 标准 OpenAI 协议路径 → default |
| `reasoning_effort` (DeepSeek) | optional | 不提供 = API 请求不含此字段，和提供任何值不同 → 保持 optional |
| `thinking` (Anthropic) | optional | 不提供 = 不启用思考模式，和启用是不同语义状态 → 保持 optional |

```typescript
  api_key: z.string(),
  model: z.string(),
  base_url: z.string(),  // 必填——代理地址
  tag_style: z.enum(["deepseek", "glm", "minimax", "default"]).default("default"),
  backend_provider: z.enum(["anthropic", "google", "openai"]).default("openai"),
  enable_thinking: z.boolean().default(false),
  edit_backend: z.enum(["str-replace", "freeform-patch"]).default("str-replace"),
});

const DeepSeekProviderConfigSchema = z.object({
  provider: z.literal("deepseek"),
  api_key: z.string(),
  model: z.string(),
  base_url: z.string().default("https://api.deepseek.com"),
  tag_style: z.enum(["deepseek", "glm", "minimax", "default"]).default("deepseek"),
  enable_thinking: z.boolean().default(false),
  reasoning_effort: z.enum(["high", "max"]).optional(),

const ProviderConfigSchema = z.discriminatedUnion("provider", [
  OpenAIProviderConfigSchema,
  AnthropicProviderConfigSchema,
  GoogleProviderConfigSchema,
  OpenAICompatibleProviderConfigSchema,

]);
```

## 架构决定

1. **默认值作为 ConfigSource** — 不做特殊 "default" 逻辑。调用方将默认 TOML 作为 sources 的第一个元素传入（name="默认"），trace 天然正确。

2. **extend 语义** — `{ ...target, ...ownFields }`。own 字段始终覆盖 target 同名字段，不允许 extend 结果中出现 `extend` key。

3. **单套 ProviderConfig** — 不再有 LLMConfigTOML + ProviderConfig 两套 schema。ProviderConfig 字段名与 TOML/API 一致（snake_case），不做命名风格转换。config-from-config.ts 已删除。

4. **config 模块零业务依赖** — 只依赖 `smol-toml` + `zod`。不依赖 `@n0n/llm`、`@n0n/types`。

5. **各 variant 自包含** — 不共享 base schema，因为不同 provider 的同名字段语义不同（如 base_url 必填性）。

6. **parse, don't verify** — 有默认值的字段在 zod parse 时填入，消费方拿到确定类型，不存在不确定传播。

## TOML 格式约定

```toml
# providers 块 — 可复用的 LLM provider 定义
[providers.anthropic]
provider = "anthropic"
api_key = "$ANTHROPIC_KEY"
model = "claude-opus-4-6"

[providers.anthropic.thinking]
type = "enabled"
budget_tokens = 10000

[providers.flash]
extend = "providers.anthropic"
model = "claude-sonnet"

# settings 块 — 最终消费的配置
[settings]
strip_hint = true
notify_sound = false

[settings.llm]
extend = "providers.anthropic"

[settings.editor]
extend = "providers.flash"
edit_backend = "freeform-patch"
```

- `providers` 和 `settings` 可在同一个 TOML 文件中，也可分布在多个源中
- `settings.llm` 和 `settings.editor` 通过 `extend` 引用 provider
- 项目级 TOML 可以覆盖 settings 字段或重新指定 extend 目标
- 可以省略有默认值的字段（base_url、tag_style、edit_backend 等）

## 文件布局

```
packages/config/
  package.json              → workspace 包，依赖 smol-toml + zod
  src/
    types.ts                → ConfigSource, ConfigError（可辨联合）, ConfigResult, Trace
    index.ts                → getConfig() + 内部纯函数（merge, resolveVars, resolveExtends, flattenTrace）
    __tests__/
      config.test.ts        → 17 tests

packages/llm/src/
  config.ts                 → ProviderConfigSchema（discriminated union on provider，SSOT）
  factory.ts                → createLLMClient（直接读 pc.tag_style，无需 detectTagStyle fallback）
  responses-client.ts       → ResponsesClientConfig（snake_case）
```
