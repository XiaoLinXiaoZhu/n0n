# 重建 02：覆盖校验与内容追踪（工程记录）

本文是工程记录层文档，不注入运行时。它记录旧体系（`data/skills/self-function/` 现行 6 个 SKILL.md）的全部实质内容在新标准草案（`docs/ie/rebuild/draft/`）中的落点，用于证明重建没有丢失已被验证有效的要求。

方法：以旧文件的实质规则为清单逐条查找新条款。旧文件仅作被检查的素材，不作为新结构的来源（活跃约束 C1）。

状态含义：**保留**＝要求不变，仅重写形式；**强化**＝要求变严或补齐了缺失的部分；**消解**＝原本集中在跨切面清单中的要求被拆回各自动作章；**移除**＝有意不进入标准，理由见第三节。

## 三、有意移除的内容

| 移除项 | 理由 |
|--------|------|
| O/D 评分、DFMEA 术语、评分锚点 | GT 第五节：属工程记录层。标准中出现会导致评分调整触发契约变更，且这些术语在运行时无定义（旧体系 `F1:31-33` 使用而未定义，违反自包含） |
| "为什么这个功能存在"的长篇动机 | 改为每条要求后一行"依据"，与要求同处一行，读到要求即读到理由 |
| 独立的"预防措施"与"探测方式"复述节 | 旧体系中占 86 行（18%），是表格内容的原句缩写，无新增信息 |
| 把具体工具命令作为所有项目的无条件要求 | 属项目层信息，随项目变化；标准写"类型检查与既有测试"，A.2 规定工具链识别顺序，并仅在条件成立时给出 TypeScript/Bun 示例 |
| 执行产物的具体路径 | 同上，属运行环境说明 |
| "thinking 第 N 步"的流程编号 | 该流程定义在不注入的文档中，属悬空引用。新体系以四阶段替代 |

## 四、结论

旧 F0-F5 的 25 个子功能项与其下全部实质规则，在新标准中均有落点：其中 4 组跨切面清单被消解到具体动作条款，其余保留、调整或强化。旧 `apps/code/src/prompts/code.md` 的覆盖属于首次重建遗漏，已在 `07-system-prompt.md` 单独逐条追踪，并由 D1.6、D2.2.6、D2.3.8、D4.1.3 补齐缺口。

本文原记录的草案规模基线为 645 行、138 条（旧体系 479 行、25 项）。后续 D1 与旧系统提示词审计增加了条款；当前规模应由仓库重新统计，不再手工维护在本段。
