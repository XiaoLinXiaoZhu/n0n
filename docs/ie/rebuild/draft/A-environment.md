# 附录 A 环境与工具口径

## A.0 地位与边界

本附录是本标准的规范性组成部分，与正文条款同等有效。

正文规定要求，本附录规定在当前环境下满足这些要求的具体口径。两者分开的原因是：要求是长期契约，口径随环境与项目变化。本附录的修订不触动正文条款；正文以条目编号引用本附录。

边界：**能由工具接口自身说明的内容不写入本附录**。工具的参数语义、返回结构、限额、产物位置由工具定义与运行时提示承载；本附录只收录工具接口无法自述的环境特性与项目口径。

## A.1 调用的提交与分批

工具调用按提交顺序执行。因此存在先后依赖的调用可以放在同一批内提交，不需要为等待上一步而拆分响应。

需要分批的情形只有一种：后续调用的内容取决于前一个调用的输出——你必须先看到结果，才能决定接下来做什么。

## A.2 项目工具链

| 用途 | 命令 | 实测耗时 |
|------|------|---------|
| 类型检查 | `bun run tsgo --noEmit` | 数秒 |
| 运行测试 | `bun test` | 约 15 秒 |
| 格式化与静态检查 | `bunx biome check --write <路径>` | 毫秒级 |
| 依赖管理 | `bun add` / `bun remove` | 数秒 |

运行测试与类型检查时应显式设置等待上限：它们的耗时接近默认值，不显式设置会频繁转入后台，多花一轮去取结果。

## A.3 补丁方式

对不宜整体重写的文件（比如他人项目、配置文件、已存在非ai撰写的代码），使用文本查找替换实现编辑。
对于一个文件的多次编辑可以一次性发出，它们会按照输出顺序逐个完成替换。替换时确保匹配项只有一个，否则应该包含更多上下文内容以辅助定位。

## A.4 隔离安装

试验性使用第三方库时安装到临时目录；Python 使用 `uv` 建立独立环境。不写入主项目依赖。

## A.5 脚本形式的选择

- 复杂数据处理（解析 JSON、过滤数组、生成结构化摘要）写成 `bun` 脚本，不用多层命令拼接。
- 简单命令（`git status`、`ls` 一类）直接执行，不包装成脚本。
- 运行 TypeScript、Python 等代码时直接指定运行时，不通过默认 shell 调用解释器执行内联代码。

## A.6 版本控制操作

提交信息先写入文件，再由该文件创建提交，避免命令行引号与换行处理导致截断。

## A.7 检索与提取工具

跨文件搜索使用 `rg`；结构化数据提取使用 `jq` 或脚本。工具的可用性以当前环境为准，不假定未经确认的命令存在。
