# Self-Function 概念体系与心智模型

本文是 self-function 体系的概念基础（ground truth）。后续一切关于 self-function skill 的设计、重写、变更，必须首先与本文一致；与本文冲突的，以本文为准，并启动本文的受控修订。

## 一、根本事实

agent 的每一轮工作都是**投产**——投产后撤回成本极大的生产活动。

历史上有三个关于 ai agent 的错误观念，本体系明确拒绝：

1. "反正是 AI 做的，质量不重要"。
2. "可以回退，做错了也没有多大关系"。
3. "最终 review 负担丢给人类"。

它们错误的原因：

1. 重复的修改和 patch 浪费用户大量时间，用户体验的损失是真实的。
2. 错误的历史记录同样让模型性能下降——错误是会被学走的。
3. 把 review 转嫁给人类并缺少契约，导致返工增加；而返工的代价极大——不仅没有降低人类工作量，反而增加了。

## 二、心智模型

- **用户 = 客户**：下订单的一方，有权要求质量。
- **模型 = 收到委托生产的企业/工厂/专家**：承担生产责任与质量责任的一方。
- 用户的每一次请求 = 一份订单。
- 模型的每一轮工作 = 一个生产周期。

## 三、工业工程质量组织的构成

工业工程面对"投产后撤回成本极大"这一事实，发展出了成熟的质量组织。本体系完整借鉴其构成：

1. **有效的交流和沟通**——客户与生产方之间的信息传递有规范、有确认。
2. **分阶段的推进契约**——生产按阶段推进，每个阶段有确认门（gate），未通过不得进入下一阶段。
3. **行业内的标准规范**——定义合格与不合格的体系标准，约束所有生产活动。
4. **系统的风险扫描和确认**——投产前对失效模式的系统识别、评估与确认。

## 四、Self-Function 的地位与位置

**地位**：Self-Function 生产质量标准是体系/行业层面的**标准规范文档——质量契约**。类似车轮生产中的行业标准与质量协议：约束体系内所有生产活动，定义什么算合格的生产、生产过程必须满足什么要求、不合格怎么判定。

**位置**：标准通过 init skill 成为生产周期的稳定上下文前缀（见
`apps/code/src/headless.ts`、`apps/code/src/repl/index.ts`），并随该周期的每次模型请求发送。
恢复同一生产周期时延续原有上下文，不把恢复动作当作标准刷新。这意味着标准在生产开始时自动生效——
是生产的前提约束，不是模型自己选择读取的工具。

**内容形态**：标准文档，包含：
- 范围（这个标准约束什么）；
- 术语与定义（自包含——标准不引用模型看不到的外部概念）；
- 要求条款（规范语言、稳定编号——条款是体系的契约条款）；
- 合格判据（每条要求如何验证）。

失效模式在标准中的位置是**要求的依据**：说明为什么有这条要求、它对抗什么失败。失效模式是要求的理由，不是标准的正文形态。

## 五、文档分层

| 层 | 内容 | 性质 |
|----|------|------|
| 标准规范（`data/skills/self-function/production-quality/SKILL.md`） | 合格生产的要求与合格判据 | 生产的前提契约，在生产周期开始时自动生效 |
| 工程记录（标准维护文档） | FMEA 分析、S/O/D/AP 评估、条款追踪、变更历史 | "这份标准为什么这样定"的受控记录 |

变更流程：先改工程记录（分析、评估、决策），再改标准（要求条款）。标准变更必须走受控流程，不得无记录地改动契约条款。

## 六、分阶段推进契约

生产按 APQP 式阶段推进，每个阶段有确认门：

1. **契约确认**——理解客户要求、澄清歧义、确认需求契约。
2. **风险扫描**——对照已知失效模式，系统识别本轮的高风险点并评估后果。
3. **生产执行**——按标准执行过程控制（安全、质量、规范）。
4. **验收交付**——全部合格判据逐项核对通过后，才可交付；交付附带质量证据。

## 七、质量目标

- **一次做对，交付即合格。**
- 人类 review 是**验收**（确认质量证据），不是返工发现。
- 返工的责任在生产企业（模型），不在客户（用户）。
