## 1. 地位、优先级与维护

本文不定义合格或不合格生产，也不提供与
`data/skills/self-function/production-quality/SKILL.md` 并列的质量要求。满足或不满足本文中的偏好，
都不能单独证明生产合格或不合格。

这些偏好不能覆盖：

1. 客户订单中的结果、范围、约束和授权；
2. Self-Function 标准规定的生产责任、证据和合格判据；
3. 系统权限与安全边界；
4. 当前真实工具接口的参数、返回、副作用、并发和暂停行为。

每项偏好只在其工具、项目、运行时或模型条件成立时适用。条件未确认、已经改变或与更上位来源冲突时，
该偏好不适用；生产方应回到负责该事实的来源取得当前口径。

偏好的物理放置遵循责任层：

| 内容 | 负责层 |
|---|---|
| 跨项目的调用、检索、编辑和隔离策略 | 运行时提示 |
| 工具能力、参数、调度、并发和返回事实 | 工具定义 |
| 仓库命令、目录、格式和本地流程 | 项目上下文 |
| 只针对特定模型的隐藏生成格式 | 模型适配器 |

工具或运行时事实变化时，先修改负责该事实的实现和本文的对应记录；项目事实变化时修改项目上下文；
模型行为变化时修改模型适配器。此类变化不修改质量标准，除非另有根本事实证明稳定质量关系本身缺失。

## 2. 运行时与工具行为

### 2.1 当前调度事实

**来源**

- `packages/core/src/agent/scheduler.ts:75-100`、`packages/core/src/agent/scheduler.ts:127-178`
- `packages/tools/src/session.ts:42-43`、`packages/tools/src/session.ts:95-105`

- `packages/tools/src/exec/definition.ts:40-47`

**适用条件**

仅适用于上述实现仍代表当前运行时、且实际暴露的工具定义没有给出不同语义的会话。

当前 scheduler 使用有序队列，只检查队首调用是否满足该工具的 `canStart` 条件。调用按入队顺序开始，
但工具可以允许并行，因此完成事件不保证按提交顺序到达。没有自定义 `canStart` 的工具默认等待所有活动调用结束。

当前 exec 工具定义说明，同一响应内的 exec 调用按提交顺序执行。当前 write 工具对不同路径允许并行，
对相同路径串行。模型仍以本轮实际收到的工具定义为事实来源，本文只是带日期的实现快照。

### 2.2 调用合并与分轮偏好

**来源**

- 当前 exec 工具定义：`packages/tools/src/exec/definition.ts:40-47`
- 历史工具链附录：`data/skills/self-function/A-toolchain/SKILL.md`

**适用条件**

后续调用的内容、是否应执行以及必要的安全检查在看到前序结果前都已确定，并且当前工具接口提供所需的顺序或并发语义。

条件成立时，倾向在同一响应中提交互不依赖的调用，或提交已经完全确定的顺序调用，减少无信息价值的往返。
若若干确定性步骤更适合由一个脚本统一编排、检查和输出，也倾向使用一个可审查脚本。

以下情形倾向分轮：

- 后续调用的内容取决于前序输出；
- 是否继续执行取决于前序成功、失败或观察结果；
- 当前接口要求确认、等待或不提供所需顺序；
- 并发会增加副作用、误覆盖、输出混淆或恢复风险。

该偏好不把“同一响应提交”解释为“完成顺序相同”，也不要求为批处理而跳过结果检查。

## 4. 编辑偏好

**来源**

- 当前 write 工具定义：`packages/tools/src/write.ts:33-45`
- 历史工具链附录：`data/skills/self-function/A-toolchain/SKILL.md`

**适用条件**

当前编辑接口支持带上下文的补丁或文本替换，且目标是需要保护未改区域的既有手写代码、配置或客户产物。

条件成立时，倾向使用范围受限的补丁或文本查找替换，避免为局部修改整体重写文件。替换目标应唯一；
若不能唯一匹配，增加足以定位的上下文。多个互不冲突的修改可以在接口保证应用顺序时合并为一次补丁。

这不是普遍编辑规则。生成文件、适合完整重建的短文件、要求领域专用工具的格式，或只提供完整内容写入的工具，
可以采用其他方法。当前 n0n write 接口只接受完整文件内容并执行创建或覆盖，因此不能从本文推断该接口支持文本替换。
实际选择仍以减少误覆盖、遗漏和不可审查差异为目标。

- 稳定质量边界：`data/skills/self-function/production-quality/SKILL.md` 7.5

**适用条件**

第三方库只用于探索或验证，不是订单要求加入项目的正式依赖，且运行环境允许创建隔离的临时位置。

倾向把试验性依赖和产物放在临时目录或独立环境，不修改主项目的依赖清单、锁文件、共享配置或长期环境。
Python 试验在 `uv` 已确认可用且适合当前环境时，倾向用其创建或运行独立环境。

若客户订单要求正式引入依赖，或项目口径要求用项目环境验证，则不套用“不得写入项目”的试验偏好；
该动作按正式项目变更处理，使用项目认可的方法并纳入验收。无论采用何种具体手段，
“试验不得污染客户长期环境”的稳定要求仍由标准 7.5 约束。

## 6. 模型适配偏好

**来源**

- `data/skills/self-function/B-chain-of-thought/SKILL.md`

**适用条件**

模型适配器能够设置不向客户显示的分析提示，并且实测表明该模型从这种提示中受益；
提供方策略和模型接口没有禁止或替代该格式。

对满足条件的模型，适配器可以偏好让内部分析以 `We need to` 开头并使用英文。
该偏好只属于模型适配层，不属于运行时通用协议、项目上下文或 Self-Function 标准。

是否遵循该格式不会产生可观察的质量证据，也从不是生产过程或交付的验收条件。
不得要求模型向客户公开隐藏分析，不得从用户可见文本反推该偏好是否执行，
也不得因模型没有隐藏分析通道或使用其他内部格式而判定生产不合格。
