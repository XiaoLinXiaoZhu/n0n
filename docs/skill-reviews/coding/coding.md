# coding

> 来源：builtin | 激活：auto

## A. 类型组成

**Methodology**（主要）。编码实践的规则集合，没有步骤序列，是一组并行生效的约束。

## B. 作用与核心思想

定义编码过程中的微观决策标准：什么时候加注释、什么时候加错误处理、什么时候抽象、什么时候重写文件。

四个维度：
1. **改动标记**——TODO/XXX 的使用规范，决策变更记录
2. **错误处理**——只在系统边界验证，信任内部路径，枚举替代布尔
3. **抽象原则**——不为一次性操作创建 helper，三行相似代码优于过早抽象
4. **注释哲学**——默认不写，只写 WHY，代码是唯一事实来源

核心思想：**最小化行动**。每条规则都在压缩模型的行动空间——不该加的不加（错误处理、注释、抽象），该加的加（TODO 标记、决策记录）。

## C. 与执行工具和 progress 的结合潜力

**间接结合**。coding skill 不直接编排工具使用，而是在模型使用 write/edit 时约束其行为——写什么样的代码、加什么样的注释。

与 progress 没有直接关系——coding skill 不定义步骤，因此没有 progress 报告格式。

**注意**：当前 system prompt（code.md）中的 "Writing code" 一节与 coding skill 有大量重复。这是需要解决的冗余问题，但按你的要求暂不处理。

## AI 回应

非常好的问题。coding 确实不应该需要手动激活——它是"不论何时都需要的标准"。

在新的分类体系中，coding 被归为 **Standard** 而非 Task。Standard 的本质就是"无论做什么任务都适用的底层规则"。

实际处理建议：coding skill 应设为 auto activation。更进一步，可以考虑将其内容并入 system prompt（因为它几乎总是需要的），或者保持 skill 形式但确保默认激活——后者的好处是迭代更快（改 SKILL.md 而非 system prompt 代码）。
