# writing-shape (mattpocock, in-progress)

> 来源：mattpocock/skills/in-progress | 激活：auto

## A. 类型组成

**Methodology**（主要）+ **Directive**（次要，交互调制器）。从原始素材到成品文章的塑形流程。

## B. 作用与核心思想

接收一份原始素材文件（fragments、笔记、草稿、转录），通过对话式塑形产出一篇文章。

循环流程：
1. 读完整份原始素材
2. 产出 2-3 个候选开头（每个暗示不同的论点/角度），用户选一个
3. 逐段生长——"given this opening, what does the reader need to hear next?"
4. 每段争论格式（散文 vs 列表 vs 表格 vs 引用 vs 代码块 vs 高亮框）
5. 边讨论边写入文章文件

关键设计：
1. **原始素材是矿场不是脚本**——拆分、重组、改写 fragment 来适配文章，不是按顺序复制
2. **争论每个格式选择**——散文承载论证、列表承载平行项、表格承载重复结构。每个选择都要有理由
3. **命名缺口**——如果原始素材缺少文章需要的内容，明确指出而不是编造
4. **反驳式质检**——"如果删掉这段，什么会 break？""这段散文还是应该做列表？为什么？"

核心思想：**写作是对话式的判断过程，不是生成过程**。模型不是"写手"，而是"共同编辑"——每段内容、每个格式选择都是双方讨论的结果。

## C. 与执行工具和 progress 的结合潜力

**中等潜力**。与 writing-beats 类似：
- 读原始素材 → observe
- 每段写入 → write
- 格式争论 → progress(blocked)（"下一段应该用列表还是散文？理由如下..."）
- 完成 → progress(completed)

三个 writing skill 形成一个管道：fragments（发散）→ shape 或 beats（收敛/组织）→ 成品文章。

**值得借鉴的内容**："争论格式选择"的模式——不默认使用散文或列表，每次都要有明确理由。这个原则对代码文档、技术写作同样适用。
