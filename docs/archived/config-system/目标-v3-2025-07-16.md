# 配置系统重构 — 目标与架构

版本 3（最终），2025-07-16

## 目标

将 n0n 配置从环境变量前缀切换重构为基于 TOML + zod schema 驱动的配置系统。

新模块 `packages/config` 是一个**通用的 TOML 配置加载器**——不包含业务领域知识，只做机械的类型收窄。

---

## API

```typescript
interface ConfigSource {
  name: string;      // 来源名称（"默认"、"全局"、"项目"），用于 trace
  content: string;   // TOML 文本
}

type ConfigResult<T> =
  | { success: true; data: T; trace: Record<string, { value: unknown; source: string }> }
  | { success: false; errors: ConfigError[] };

function getConfig<T>(
  schema: z.ZodType<T>,
  sources: ConfigSource[],
  envPool?: Record<string, string>,
): ConfigResult<T>;
```

---

## 处理流程

```
sources[0].content → TOML parse
sources[1].content → TOML parse
...
  ↓ deep merge（后者深度覆盖前者，来源注释随之更新）
merged JSON
  ↓ walk: 所有 string 值 → 匹配 /^\$[A-Z_][A-Z0-9_]*$/ → 从 envPool 替换
$VAR resolved
  ↓ walk: 含 extend 字段的 object → 递归展开 { ...target, ...ownFields }
extend resolved
  ↓ zod schema.parse()
T（类型安全输出） + trace（dot-path → {value, source}）
```

---

## 核心机制

| 机制 | 行为 |
|------|------|
| **多文件合并** | sources 数组顺序解析为 JSON，后者深度覆盖前者。同级 section 深度合并，标量值替换 |
| **`$VAR`** | 字符串值匹配 `/^\$[A-Z_][A-Z0-9_]*$/` 时从 envPool 查找。未找到→ `env_var_not_found` 错误。`$` 后非大写字母不触发替换 |
| **`extend`** | 保留字段，值为 dot-path 字符串。解析时替换为 `{ ...resolve(target), ...ownFields }`（own 覆盖 target），然后移除 `extend` key。链式递归，环检测 |
| **zod 验证** | extend 解析后的 JSON 传入 `schema.parse()`。额外字段被忽略（zod 默认行为） |
| **trace** | 每个叶子值的最终来源记录在 trace 中。来源按合并/覆盖顺序传递：默认 → 全局 → 项目，extend 目标的来源继承到引用方 |

## 错误类型（可辨联合）

| kind | 说明 |
|------|------|
| `toml_parse_error` | TOML 语法无效 |
| `env_var_not_found` | `$VAR` 引用的环境变量不存在 |
| `extend_target_not_found` | extend dot-path 目标不存在或不是 object |
| `circular_extend` | extend 链存在循环 |
| `schema_validation_error` | zod parse 失败 |

---

## 架构决定

1. **默认值作为 ConfigSource** — 不做特殊 "default" 逻辑。调用方将默认 TOML 作为 sources 的第一个元素传入（name="默认"），trace 天然正确。

2. **extend 语义** — `{ ...target, ...ownFields }`。own 字段始终覆盖 target 同名字段，不允许 extend 结果中出现 `extend` key。

3. **双套 zod schema** — `LLMConfigTOMLSchema`（snake_case，描述 TOML 解析后的 settings.llm/editor）和 `ProviderConfigSchema`（camelCase，运行时 discriminated union）。`config-from-config.ts` 负责映射。

4. **config 模块零业务依赖** — 只依赖 `smol-toml` + `zod`。不依赖 `@n0n/llm`、`@n0n/types`。

## TOML 格式约定

```toml
# providers 块 — 可复用的 LLM provider 定义
[providers.anthropic]
type = "anthropic"
api_key = "$ANTHROPIC_KEY"
model = "claude-opus-4-6"
thinking = true
thinking_budget_tokens = 10000

[providers.flash]
extend = "providers.anthropic"
model = "claude-sonnet"
thinking = false

# settings 块 — 最终消费的配置
[settings]
strip_hint = true
notify_sound = false

[settings.llm]
extend = "providers.anthropic"

[settings.editor]
extend = "providers.flash"
```

- `providers` 和 `settings` 可在同一个 TOML 文件中，也可分布在多个源中
- `settings.llm` 和 `settings.editor` 通过 `extend` 引用 provider
- 项目级 TOML 可以覆盖 settings 字段或重新指定 extend 目标

```

  src/

```
