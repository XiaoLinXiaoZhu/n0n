# 配置系统重构 — 目标与架构

版本 1，2025-07-16

## 目标

将 n0n 配置从环境变量前缀切换（`N0N_PREFIX`）重构为基于 TOML 的 Named Providers + Role Assignment。

## 架构决定

### 模块位置

`packages/config`，作为 workspace 包，依赖 `smol-toml`。

### 设计原则

1. **parse, don't verify** — 输入时解析为判别类型，不含 `?` 可选字段。解析失败返回可辨联合错误类型。
2. **纯函数** — `parse`、`resolve`、`merge` 均为纯函数，不耦合 I/O。`load` 是唯一带 I/O 的入口。
3. **config 与 apps 解耦** — config 只做机械类型收窄，不关心字段被如何使用。连通性测试、交互式创建均在 apps 层。

### 核心机制

- **`$VAR`** — TOML 字符串值以 `$` 开头时解析为环境变量引用，从 envPool 查找。找不到时报错。
- **`extends`** — Provider 通过 `extends = "parent_name"` 继承，支持链式、环检测。child 字段覆盖 parent。
- **两层合并** — global（`~/.n0n/config.toml`）+ project（`$PROJECT/.n0n/config.toml`）。project 覆盖 global。
- **Role 分配** — `roles.llm` 必填，`roles.editor` 可选（fallback 到 `roles.llm`）。值必须是已定义的 provider 名。
- **`edit_backend`** — provider 级别属性，描述当此 provider 用作 editor role 时的编辑后端（`"str-replace"` | `"freeform-patch"`）。
- **CLI override** — `--llm <name>` 覆盖 `roles.llm`。

### .env 仅存 secrets

```
ANTHROPIC_KEY=sk-ant-xxx
DEEPSEEK_KEY=sk-ds-yyy
```

TOML 通过 `$ANTHROPIC_KEY` 引用。

## 文件布局

```
packages/config/
  package.json
  src/
    types.ts    — 所有判别类型（RawConfig、ResolvedProvider、ResolvedConfig、错误类型等）
    parse.ts    — parse(toml, envPool) → ParseResult（纯函数）
    resolve.ts  — resolve(raw) → ResolvedConfig（extends + role fallback，纯函数）
    merge.ts    — merge(global, project) → ResolvedConfig（纯函数）
    load.ts     — loadConfig(globalDir, projectDir?, cliLlm?) → LoadResult（带 I/O）
    index.ts    — 统一导出

packages/llm/src/
  config-from-config.ts  — ResolvedProvider → ProviderConfig 映射（替代 config-from-env.ts）
```

## 删除的旧代码

- `packages/shared/src/bootstrap/` — 全部四个文件
- `apps/code/src/env-spec.ts`
- `packages/llm/src/config-from-env.ts`

## 依赖关系

```
apps/{code,fairy}
  → @n0n/config（loadConfig）
  → @n0n/llm（config-from-config、createLLMClient）
     → @n0n/config?（仅类型导入，不是依赖）
       ↑ 如果 llm 需要类型，通过 workspace deps 引用
```

`@n0n/config` 无内部依赖（仅 `smol-toml`），不依赖 `@n0n/llm` 或 `@n0n/types`。

## 不向后兼容

config.toml 不存在时报错。旧 .env 系统完全移除。
